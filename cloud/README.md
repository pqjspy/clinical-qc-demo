# 质控工作台 · 云端实时演示

线上地址：[云端实时 Demo](https://clinical-qc-public-demo.pqjspy.workers.dev)

这是一份独立部署副本，不改变 `../frontend`、本地 8911 服务、账号、历史记录或封存评测。

以下功能与预算描述已部署的 `cloud-rag-v2` 实现。2026-09-14完成真实检索评测、部署及3条线上流程检查，详见[部署验证](DEPLOYMENT_CHECK.md)。核对线上 `/api/health` 的 `version`、`retrieval_version` 与模型标识；建立访客会话后可从 `/api/library` 的 `id` 核对bundle。旧运行结果保持原样，新增检索面板仅在重新分析后显示。

## 功能

- Cloudflare Workers AI 实时调用 `@cf/qwen/qwen3-30b-a3b-fp8`，不是答案回放。与本地 Qwen 型号不同。
- 短文本先按研究、中心、方案和事件日期过滤规则，再调用 `@cf/baai/bge-m3` 生成向量并计算余弦相似度，与 BM25 通过 RRF（k=60）融合；前8条候选送入真实交叉编码器 `@cf/baai/bge-reranker-base`，重排后最多4条规则原文作为 Qwen 分项的参考上下文。普通v1范围只有6条适用规则，实际候选不会补足到8条。
- 复用原 Python 六类事实解析、适用范围过滤、BM25、计算及三级分类程序；确定性检查仍拿到完整规则库，按原有适用条件检查，不受检索前4条限制。检索相关性分数不是风险概率，不能解决规则冲突。通过 `prepare.py` 按明确清单生成并校验文件哈希。
- 原文片段完整覆盖校验；缺失、冲突、歧义和未知问题保留为未决，不自动通过。
- AI 生成解释草稿；引用编号校验不等于语义正确。保留原草稿；只有合法的逗号分组引用会被规范成独立方括号，仍逐个校验归属。
- D1 保存访客自己的记录、不可覆盖的 AI 初判、逐项人工修改和复核版本；过期或不同访客不能读取。
- 公开规则库只读，不提供本地账号登录、规则发布或旧模型评测接口。

仅允许合成资料。访客复核是流程演示，不验证医务身份，不构成医学授权、电子签名或正式合规结论。

## 免费边界

部署于已核实的 **Workers Free** 账号，没有升级套餐、添加付款方式、购买 AI Gateway 额度或设置付费回退。

| 限制 | 设置 |
|---|---|
| 每日分析 | 全站 40 次 / 每访客 6 次 / 每 IP 12 次，按 UTC 日期 |
| 同时分析 | 全站最多 3 条，同访客最多 1 条 |
| 单条输入 | 最多 2400 字、40 个片段、8 个问题 |
| 增强检索短文本预算 | 完整原文及每条规则引文各最多256字符；普通v1适用池6条，候选K=8、最终K=4 |
| 每次分析的 AI 调用 | 最多4次：1次向量批处理＋1次重排＋最多2次Qwen；没有自动重试 |
| 每次调用超时 | 向量、重排各18秒；Qwen分项、解释各24秒；不是整个分析的总超时 |
| 输出预算 | 分项 1100 tokens；解释 1500 tokens |
| 保存容量保险上限 | 2000 访客、2000 自建记录、1500 次分析；每访客 30 条自建记录 |
| 每次运行的复核 | 最多 50 版本；提醒操作最多 30 次 |

Cloudflare 自己的每日免费额度可能比应用限额先用尽，届时请求失败而不是转为付费。**40 次不是对所有输入都能运行的保证**。容量保险上限累计计算；达到后需由项目所有者检查并清理过期演示数据，不能通过升级付费绕过。

原文超过256字符（但在2400字总上限内），或任一适用规则引文超过256字符时，保留完整输入，明确记录增强检索 `not_applicable` / `legacy_bm25_only`，继续原有逐项BM25流程，不执行向量和重排。没有适用规则时同样跳过检索模型，不代表没有问题。真正的检索调用失败会留下失败状态，不能冒称完成重排。没有微调、向量数据库、嵌入缓存或付费服务回退。

## 检索评测

2026-09-14 用18条新编合成检索查询完成34次真实 Workers AI 调用：17条有适用候选的查询各调用一次BGE-M3和一次BGE-reranker-base，另1条没有适用研究规则，不调用模型。此评测没有调用Qwen，不是M4的18条质控分类评测，也不验证端到端分类或解释质量。

固定评估集为12条，其中11条有参考目标、1条无目标。下表只对11条有目标查询计算指标，失败保留在分母并记0；本次各方法失败数均为0。

| 方法 | Recall@1 | Recall@3 | MRR | nDCG@3 |
|---|---:|---:|---:|---:|
| BM25 | 0.5000 | 0.9091 | 0.7803 | 0.7965 |
| Dense（BGE-M3＋余弦） | 0.8636 | 1.0000 | 1.0000 | 1.0000 |
| Hybrid（RRF） | 0.7727 | 1.0000 | 0.9545 | 0.9664 |
| Hybrid＋BGE重排 | 0.7727 | 1.0000 | 0.9394 | 0.9545 |

无目标查询在四种方法下均成功返回空排序，单列为1/1，不混入上表分母。另6条开发查询四项指标均为1.0000，单独报告，不与评估集成绩混用。重排没有超过Dense，且本次MRR低于未重排的Hybrid；不能宣称增加重排必然提高质量。知识库仅9条版本化规则，通常过滤后仅6条，v2探针甚至只有1条，因此不支持真实医院准确率或大规模知识库泛化结论。数据、参数、指标定义与可复现入口见[混合检索 v2 说明](../docs/RETRIEVAL_V2_ZH.md)。

## 会话、保存和隐私

- 浏览器获得随机访客凭证；数据库只保存凭证哈希，Cookie 为 HttpOnly / Secure / SameSite=Strict。
- 所有写入检查同源和 CSRF；所有记录、运行、导出、复核接口均按服务端访客身份过滤。
- 会话有效 7 天。清除 Cookie 或凭证过期后不能恢复旧记录；需要保留时请提前导出。
- 数据在云端保存，不是只保存在浏览器。没有声称到期自动擦除，也不提供真实患者资料处理承诺。
- 只保存按日变化的 IP 哈希用于配额；不在模型提示或结果里加入 IP / 访客凭证。
- 迁移不复制 `runtime/`、密码、原有 SQLite 或参考答案。

## 构建与部署

在 `clinical-qc-demo` 目录：

```sh
.venv/bin/python cloud/prepare.py
.venv/bin/python cloud/adapt_frontend.py
.venv/bin/python cloud/test_cloud.py
.venv/bin/python cloud/test_semantic_retrieval.py
npm --prefix cloud/frontend ci
npm --prefix cloud/frontend run build
```

在 `cloud` 目录，保证 `uv` 在 PATH 中：

```sh
uv run pywrangler dev --config wrangler.jsonc --port 8922 --ip 127.0.0.1
uv run pywrangler d1 migrations apply DB --remote --config wrangler.jsonc
uv run pywrangler deploy --config wrangler.jsonc
```

始终明确传 `--config wrangler.jsonc`，避免采用上级其他项目的配置。依赖版本由 `uv.lock`、`pylock.toml`、`package-lock.json` 锁定。数据库 ID 在配置中明确固定。

## 验证

`test_cloud.py` 为软件测试：12 个演示输入、原程序哈希、严格输出、复核不可变、SQL 隔离和配额。使用人工指定路由，不是模型准确率评测。新增检索相关的软件检查和真实模型评测须分别记录；[检索 v2 说明](../docs/RETRIEVAL_V2_ZH.md)提供离线检查和真实评测命令。

`smoke_http.py --url <线上地址>` 验证会话、CSRF、另存重开和访客隔离，不调用 AI。显式加 `--live --enhanced` 最多执行 3 条真实分析：27 分钟、PK+AE 双问题、30 分钟边界；同时检查四路排名及实际检索模型调用、复核追加与跨访客拒绝。它允许解释被校验拦截后转人工，但必须保留程序结果；详细状态须另报，不能将此测试通过解读为全部解释有效。

本地预览的 AI 绑定仍访问云端，不是免费离线模型。此次网络中预览代理报连接中断，而公网 Worker 可以调用 AI。

本机 DNS 曾把 `*.workers.dev` 解析到错误地址。诊断时通过 Cloudflare 官方 DNS-over-HTTPS 查询确认地址，再仅对测试请求指定解析地址；始终保留原主机名与 TLS 证书校验，**不改系统 DNS / hosts，不关闭 HTTPS 校验**。`--resolve` 只供这种已核对 DNS 的诊断，不应硬编码过期 IP。

当前验证以编译、软件测试和 HTTP 接口为准；未完成浏览器逐按钮视觉验收，也未用这些少量案例宣称真实业务准确率或最大负载性能。
