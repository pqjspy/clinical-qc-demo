# 项目总览：临床试验质控 AI 分类与预警工作台

版本：设计稿 v0.1，2026-09-09；M5进度更新2026-09-10。六类显式事实执行器、多问题逐项复核与合成评测入口已实现，另交付本机启动/状态检查、私有备份和隔离恢复演练、正式方案与演示稿。当前入口见[M5交付指南](M5_START_HERE_ZH.md)，业务操作见[M4指南](M4_START_HERE_ZH.md)。推理仍明确收窄为Qwen分项/家族识别、有限语法提取事实、规则确定L3/风险、Qwen解释；不是通用LLM抽取或医院临床分类验证。下文未注明已实现的部分仍为目标设计。

## 1. 先看最终用户会做什么

一名质控人员在网页里选中一条记录：

> 【虚拟案例 QC002】采血时间 10:06，离心时间 10:33。请检查这次 PK 样本处理是否符合本研究方案。

他点击“AI 分析”。系统从已批准的虚拟规则库中找到本研究对应版本的要求：

> 【虚拟方案 SYN-STUDY-001 v1】本演示规定采血至开始离心的间隔至少为 30 分钟。

系统计算出 27 分钟，显示：

| 用户看到的内容 | QC002 的预期结果 |
|---|---|
| 一级 / 二级 / 三级 | 样本管理 / PK 样本管理 / 样本处理时间不足 |
| 风险等级 | 中，按此虚拟规则的预设策略，不是医学风险定论 |
| 建议判定 | 方案偏离（AI/规则建议，待人工复核） |
| 判断依据 | 原记录的两个时间 + 方案“至少30分钟”的原文 + 27 < 30 的计算 |
| 是否需人工复核 | 是 |
| 建议措施 | 建议由负责人员确认样本是否被中心实验室接受，并评估结果是否有效 |

用户可以点开证据，修改分类或风险，写明修改原因，然后保存人工确认结果。再次打开记录，能同时看到原始输入、AI 初判、人工修改和最终确认。

**这就是项目主线：把一条质控记录变成有依据、可复核、可追踪的处理建议。** 不是先做一堆模型分数，也不是让聊天机器人直接宣布“违规”。

QC002 的分类、27/30 分钟和中风险来自测试样例；研究编号、完整日期、演示规则及后续变体由我们合成。“至少30分钟”只在这个虚拟研究中适用，不是通用临床要求。

## 2. 本项目与旧学习项目的区别

旧项目的公开论文分类、FDA 法规检索是技术练习。本项目直接模拟测试中的业务输入与输出，不再要求先完成公开数据 benchmark。

- 输入是中文合成 QC 记录，不是论文句子或 FDA 标题。
- 知识库是虚拟医院分类树、虚拟研究方案和虚拟操作规则，不是假装已拿到医院的真实规则库。
- 最终交付是能点击操作的本地网页 + 测试要求的五部分方案。
- 旧代码仅可按需要审查后复用思路或小模块，不整体迁移旧数据、配置或未完成的 Notebook。
- 合成案例结果用于证明软件行为和演示能力，不能声称医院数据上的准确率。

## 3. 第一版包含哪些场景

先支持题目列出的六个问题家族，具体分类树由我们制定为“Demo 分类树 v1”，不是行业标准。

| 场景 | 需要观察什么 | 代码/AI需要解决的问题 |
|---|---|---|
| 访视超窗 | 计划访视、窗口、实际日期 | 正确解析日期、调用对应规则、计算是否超窗 |
| AE 漏记 | 事件原文、应登记位置、已有记录 | 区分“明确未登记”和“没有提供登记资料” |
| 样本处理异常 | 采集/处理时间、方法、方案要求 | 确认事件含义、单位和时间，再计算 |
| 试验用药管理异常 | 发放、回收、库存、台账 | 检查数量关系，解释差异；不把缺字段当零 |
| 授权职责不一致 | 人员角色、操作、授权范围/日期 | 检查该人该时点是否具备相应授权 |
| 原始记录与 EDC 不一致 | 同一虚拟受试者、字段、时点、单位 | 对齐后比较；不把不同日期或单位误认为冲突 |

还必须展示：正常/未发现问题、缺失信息、模糊记录、多个问题、规则冲突、规则版本改变、不支持的场景、模型失败。

一个记录可以拆成多个 finding（问题项）。每个问题项单独有分类、风险、证据和复核状态；不能只挑最容易的一项回答。

不匹配任何合法 L3 时，保留“无法确定/超出范围”的处理状态，分类字段可以为空。状态不是硬塞进分类树的“第七类”。没有发现问题也不能强行输出一个违规 L3。

## 4. 四个页面，完成一个闭环

1. **质控记录页**：案例列表、输入原文、研究/规则版本、分析按钮、多问题结果、可点击证据、当前真实推理/回放状态。
2. **规则库页**：四级分类树、规则文字与结构化条件、适用范围、版本；导入草稿、检查错误、由规则管理员确认发布。L4 只作为候选参考展示。
3. **人工复核与审计页**：待复核队列；高优先级提醒；确认、修改、退回补充；并列查看初判、修改原因和最终记录。
4. **评测页**：合成案例的分类、风险漏报、证据和人工转交结果，以及失败例子；明确区分单元测试、演示和封存评测。

“预警”在第一版中是本地工作台的提醒卡和待处理队列，不发邮件、短信，不触发真实临床操作。提醒状态含待处理、已查看、已转交、已关闭；关闭需记录处理人和理由，不等于风险已被医学上排除。

## 5. 系统如何工作：每个组件有明确职责

```text
虚拟QC原文 + 研究/日期等上下文
    ↓
Qwen：理解文字，拆分问题，抽取事实及原文位置
    ↓
规则检索：按研究、方案版本、适用时点过滤，找候选规则和原文
    ↓
Python：验证事实，做日期/数量/字段比较，检查规则冲突
    ↓
Qwen：基于已给证据提出合法L3候选、可读解释和建议
    ↓
校验器：核对分类路径、计算、引用、缺失信息和风险策略
    ↓
本地预警/人工复核队列 → 人工确认或修改 → 保存审计记录
```

这不是让 LLM 自由调用任意工具的 Agent。第一版是可观察的固定工作流，每一步有输入、输出、耗时、成功/失败状态。

### LLM、规则引擎、RAG 分别做什么

- **LLM**：处理自然语言，区分一句话中的多个问题，提取有来源的事实，提出分类和解释。必须真实接入本机 Qwen；不能用关键词规则冒充 LLM。
- **规则引擎**：执行确定性判断。27 分钟是否达到 30 分钟，由代码算；参数来自已批准、适用的虚拟方案，而不是 LLM 猜测。
- **RAG**：给模型提供这条记录适用的规则原文、分类定义和研究要求。这里检索的是我们自己的虚拟业务知识，不依赖模型记忆中的医学知识。
- **输出校验**：JSON 格式正确不等于事实正确。还要查合法分类 allow-list、L1/L2/L3 的父子关系、证据确切位置及计算一致性。

规则已有确定结论时，LLM 不得改写计算结果或把风险策略降级。抽取的时间、主体或否定关系不明确时，不直接计算成一个肯定结论；转为需补充/复核。

分类选择使用合法 L3 的 ID，L1/L2 由分类树回填，避免三个层级各自生成而互相矛盾。L4 在独立的“参考候选”区域，绝不显示成自动确认结论。

### 风险等级与处理优先级分开

已命中规则按虚拟风险策略给出低/中/高；信息不足时允许“待定”。风险不是模型自报的 confidence，也不是 LLM 随意写的形容词。

已知高风险线索即使分类尚不完整，也要进入优先人工处理队列；未知风险不能自动显示为低风险。记录总览显示已确认建议中的最高风险，同时明确展示未决问题数和处理优先级，不能用一个低风险汇总掩盖未决问题。

第一版所有 AI 初判均需人工确认后才成为已复核结果。转人工并不代表分类预测正确；评测时单独计算分类性能和风险转交性能。

## 6. 规则库不只是一些段落

医院真实四级规则库尚未提供，我们先创建可替换的合成版本。每条规则至少包括：

- 规则 ID、版本、四级路径、原文和位置、适用研究/方案/中心/操作对象。
- 生效区间、是否启用、与旧版的替代关系；“上传时间”不当作生效时间。
- 必需事实、判断条件、阈值、单位、运算方式、缺失事实处理。
- 命中时的 L3、建议风险/判定/措施、复核策略。

接入流程：人工整理的 JSON/YAML 或导入文件 → 字段/路径/范围校验 → 草稿预览与差异 → 管理员批准 → 发布一个新版本。文字规则可由 LLM 辅助抽取草稿，但不得直接发布成可执行规则。

多规则处理：不相关问题分别保留；同一问题的兼容规则合并依据；同范围同时间的互斥规则显式报冲突，不让 LLM 私自挑一个。明确版本替代只按已批准元数据生效。

版本更新不改写旧结果。新分析绑定新版本；旧分析继续能查看当时输入、模型/提示词版本、规则快照和输出。演示一次 v1→v2 更新及旧结果保留。

## 7. 技术选型：围绕 Demo 的实际需求

| 层 | 首版选择 | 在这个项目里的用途 |
|---|---|---|
| 前端 | React + TypeScript | 四个中文工作台页面、证据查看、复核操作 |
| 后端 | Python + FastAPI + Pydantic | API、固定工作流、字段校验、规则计算 |
| 本地模型 | Ollama + Qwen | 真实文本理解、结构化输出、带证据解释 |
| 检索 | 本地 BM25 起步 + 明确范围过滤 | 在小型虚拟规则库找依据；Dense/Reranker在有错误证据后再加 |
| 持久化 | SQLite + 数据访问层/迁移 | 保存案例、运行、规则版本、人工复核、提醒和审计事件 |
| 测试 | pytest + 浏览器端到端测试 | 核心计算、异常路由、审核闭环和演示可重复性 |
| 本地部署 | 先原生开发；最终应用容器 + 主机 Ollama | 浏览器只访问本机，不先上云/K8S |

M2已核实 `qwen3:4b-instruct-2507-q4_K_M` 的本机服务和摘要，并完成真实结构化输出与错误记录；具体环境和边界见运行报告。效果不够好时先分析错误，不自动下载更大模型或切云端。

Ollama 支持按 JSON Schema 约束输出并用 Pydantic 复验，但业务正确性还需上述校验与测试。[官方结构化输出说明](https://docs.ollama.com/capabilities/structured-outputs)

后端采用 FastAPI 的类型化 API 机制，前端采用 React 组件；具体版本在实现时锁定，不在设计稿中编造版本号。[FastAPI 文档](https://fastapi.tiangolo.com/)，[React 文档](https://react.dev/learn)

首次依赖安装可能需要网络；依赖和模型备妥后的正常分析不调用云模型。先核实本机 Docker 可用性再做容器验收，不能把已安装命令等同服务运行正常。[Docker Mac 安装说明](https://docs.docker.com/desktop/setup/install/mac-install/)

第一版不需要微调、K8S、vLLM、多模态 OCR、多个 Agent 或独立向量数据库。是否增加这些能力，应由实际需求和验证结果决定。

## 8. 人工复核、审计与隐私

保留三层结果：不可在业务界面覆盖的 AI 初判、追加的人工作业/修改理由、人工确认版本。修改分类、风险、判定或措施必须有操作者、时间和理由；再次修改生成新版本，不抹去历史。

模型失败、缺失信息、未知分类、证据不足、多规则冲突、潜在高风险和明显来源矛盾必须显式转交。不能把超时/解析错误包装为“未发现问题”。演示中的复核者是本地用户，不因此获得医学专业资质。

应用层实施角色权限：查看者、复核者、规则管理员；审计写入在后端强制，不能只禁用前端按钮。演示级追加记录不等于不可篡改监管存储，拥有本机数据库权限的人仍能改变文件；生产级防篡改是后续设计要求。

所有页面与导出带“合成数据/非临床用途”标识。不使用真实姓名、身份证、联系方式或真实病历；不上传用户提供的真实临床资料。日志默认不输出完整原文或模型提示词，完整审计快照限定本地授权访问。应用只监听回环地址，不公开端口；密钥不入库、不入代码；本地备份与重置须明确路径和确认。

这些是演示级控制和生产升级建议，不等于通过医院安全评审或任何法规认证。

## 9. 如何验证，不靠“看起来像对了”

先用12条有名字的展示案例开发，再另外编写18条记录作冻结合成回归评测。展示运行不混进这18条成绩；但本轮两者共享作者、规则与有限事实语法，部分是边界重组，不能声称做到了严格模板隔离。严格病例家族/模板独立是未来泛化评测要求。

合成时先写事实与预期标签/依据，再生成或人工改写文字。评测参考与模型输入分开存放，不让模型读取答案。若用同一个模型生成并评价，只能当辅助检查，不能当独立真值。

| 检查项 | 为什么需要 |
|---|---|
| 多问题发现 Recall + L3 Micro/Macro-F1、精确路径率 | 不能漏掉一个记录里的第二个问题，也不能只照顾大类 |
| 高风险问题漏检率、风险低估率 | “没有发现”和“发现了但标低了”分开报 |
| 高风险转交 Recall + 误预警率/人工复核量 | 不能靠所有记录都报高风险获得漂亮数字 |
| 证据位置有效率 + 声明是否受证据支持 | 引文存在不代表能推出结论 |
| 缺失/冲突/越界/模型失败的路由结果 | 拒绝编造也要测试，不只是成功题 |
| 耗时分布、失败率、审计与重放完整性 | Demo必须能运行和排错，不只是生成一个答案 |

对多问题记录，在原文问题项层面建立匹配后计算；空输入、正常记录和模型失败也保留在对应分母内。分开给出样本数、未评测类别、无支持类别处理与人工转交量，不承诺尚未测得的准确率。

首版验收底线：QC002算术与来源一致；非法路径/缺失信息不会通过；人工修改不覆盖初判；高风险展示边界不得静默丢失。模型指标如实报告，即使不理想也保留错误，不根据结果临时挪动评测题。

真实医院部署前，还需医院提供获授权且去标识的历史 QC 记录与权威规则，由专业人员独立标注/处理分歧，按研究/中心/时间防泄漏切分，开展影子运行和高风险漏报专项验证。**合成评测不能替代这一步。**

## 10. 开发顺序和最终交付

M0 设计 → M1 虚拟业务数据 → M2 单条真实 AI 流程 → M3 中文网页与复核 → M4 多场景与评测 → M5 本地部署与正式方案。

详细任务和学习方式见 [开发与学习路线](BUILD_AND_LEARN_ZH.md)。每一步先看一个具体案例，再读负责该步骤的少量代码，再做一次改变输入的练习；Notebook是可选学习辅助，不再成为完成业务 Demo 的前置条件。

最终交付：本地应用、合成数据说明、可版本化规则、可追溯演示、评测与错误报告、部署/启动指南、按测试五部分写的中文正式方案、5-10分钟演示稿。

当前已落实M1、M2单份PK、M3网页/复核、M4六类有限语法执行器/多问题处理及M5本机交付工具和答卷。M5隔离验证不改在线数据；整机断网、新机器安装及Docker未验证，详见[M5记录](M5_VERIFICATION_ZH.md)。M4网页调用新版本工作流，旧M2/M3运行不改写。分项模型仍有已记录错误；六类执行器存在不等于模型每类都预测正确。规则发布仍限追加PK版本，完整停用/更正生命周期尚未实现。评测页只读真实保存的18条冻结合成结果，不用展示答案伪造分数。旧项目未修改。
