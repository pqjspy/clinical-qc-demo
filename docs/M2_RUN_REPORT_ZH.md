## 1. QC002这次真的运行了什么

完整记录：[QC002实际运行 result.json](../runtime/runs/632923e6-e280-44aa-8502-ef01acfc1d8c/result.json)。这是保存的真实运行，不是再次打开就重新推理。

输入原文：

> 【合成虚拟记录】2026-09-01，SYN-SUBJ-002同一份PK样本的采血时间为10:06，开始离心时间为10:33，均为北京时间。请检查样本处理是否符合本研究方案。

第一次Qwen返回的完整抽取对象：

```json
{
  "scope": "single_pk",
  "scope_quote": "同一份PK样本的采血",
  "same_sample_quote": "同一份PK样本",
  "date_quote": "2026-09-01",
  "timezone_quote": "北京时间",
  "collected_time_quote": "采血时间为10:06",
  "centrifuged_time_quote": "开始离心时间为10:33",
  "other_issue_quotes": [],
  "uncertainty_quotes": []
}
```

程序核对这些引用后，从原文规范化时间；BM25在6条适用v1规则中把`SYN-RULE-PK-001@1`排第一，分数20.1455。排序不是风险分数。

Python计算：

```text
2026-09-01 10:33 − 2026-09-01 10:06 = 27分钟
规则要求：30分钟
27 < 30
```

确定建议：样本管理 → PK 样本管理 → 样本处理时间不足；中风险；建议方案偏离；需人工复核。参数、分类、风险、措施来自规则/分类树，不是模型独立猜测。

第二次Qwen返回的解释原文（保留措辞，未人工确认）：

> 实际采血至开始离心的时间间隔为27分钟，小于规则要求的最小30分钟[F5]，且该间隔基于同一份PK样本的采血时间（10:06）和开始离心时间（10:33）计算得出[F6]，符合【合成演示规则】中关于同一PK样本从采血到开始离心时间间隔至少为30分钟的规定[R1]。由于实际间隔未满足规则要求，判定为样本处理时间不足，需人工复核。

**这段草稿仍有措辞问题：**中间“符合……至少30分钟的规定”与27<30容易产生矛盾；`[F5]`本身只支持采血时间，不单独支持30分钟阈值。程序确定的比较结果没有错，但引用存在和ID合法不能证明解释每句话都正确。不能把这段文字标成“已验证结论”；它必须保留为待人工修改的模型草稿。40分钟案例的草稿还出现“来源一致”等不应额外推断的措辞。

因此当前输出明确分开：程序确定的结果、原文/规则证据、未经语义验证的解释草稿。M3人工复核界面要保留这种分离，不把草稿直接当确认结果。

### 缺信息案例的真实错误

Qwen正确把离心时间设为null，但把“未提供时间”和“提交时间不是离心时间”误放进`other_issue_quotes`，所以程序进入`unsupported_scope`。更准确的预期应是`needs_information`，另外采血引用只选了“北京时间10:06”，没有保留采血角色。

当前没有把提交12:00拿来计算，也没有生成错误的通过/违规结论，风险保持待定并转人工；**转人工安全边界得到保留，不代表分类/路由预测正确。** 本次错误原样保留，M4扩展范围时再完善缺失/歧义抽取与专项评测，不按编号硬编码修正结果。
