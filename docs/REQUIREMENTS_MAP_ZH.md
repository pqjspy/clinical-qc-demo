# Demo 功能与验收对照

更新至M5。下表列出功能与设计，当前实现状态和限制以紧接的状态说明为准；完整设计见[技术方案](TECHNICAL_TEST_SOLUTION_ZH.md)。

## 五部分功能范围

| 功能要求 | 对应功能/设计 | 演示或验收证据 |
|---|---|---|
| 1. 理解场景与总体流程 | 质控人员输入，AI建议，人工复核，规则/审计闭环 | 从QC002输入到人工确认的完整操作 |
| 1. AI三级分类和风险预警 | 合法L3候选、风险策略、本地预警队列 | 路径、风险、待复核状态、提醒状态可见 |
| 2. 接入四级规则库 | 合成分类树 + 可替换导入适配层 | 导入草稿、字段/父子路径校验、管理员发布 |
| 2. 文字规则结构化 | 文本来源、适用范围、条件、单位、阈值、风险映射 | QC002原文规则与结构化条件并列展示 |
| 2. L3自动、L4辅助 | 从L3 ID回填L1/L2；L4独立候选 | API和页面不把L4标作自动确认 |
| 2. 多命中/冲突/更新 | 多问题拆分、冲突转交、版本绑定；兼容合并为后续设计 | 一条多问题记录、一个冲突案例、一次v1/v2更新 |
| 3. 方法选择及理由 | Qwen理解和解释 + RAG规则依据 + Python确定性计算 | 显示各步骤真实输入输出；不是静态答案演示 |
| 3. 风险/依据/建议措施 | 虚拟策略、双重证据、代码结果；建议待审核 | 点开输入原句、规则引文和计算 |
| 3. 信息不足/模糊 | 未决字段、待补充、超范围状态 | 删除关键时间后不会编造结论 |
| 4. 人工确认/修改 | 查看者、复核者、管理员权限与复核动作 | 后端权限检查、修改原因、前后值 |
| 4. 初判/修改/最终记录 | 运行快照 + 追加审核事件 + 确认版本 | 重开页面仍能查看历史，旧结果不会被新版本改写 |
| 4. 不替代医学判断 | 首版所有初判需人工确认，缺失/高风险优先转交 | 页面标签、异常路径、不自动执行临床措施 |
| 4. 隐私/安全 | 全合成、回环访问、日志最小化、角色与本地备份边界 | 无真实病历、云调用和公开部署；权限拒绝测试 |
| 5. 实施计划 | M0-M5，每步可操作交付 | 开发清单、里程碑验收 |
| 5. 历史数据验证 | 写清真实数据授权、去标识、独立专家标注与分组切分方案 | 正式方案中明确尚未做真实临床验证 |
| 5. 高风险漏报 | 漏检/低估/转交/误报和工作量分别评估 | 合成高风险与多问题案例的逐项结果 |

输出字段包括：一级、二级、三级、风险等级、建议判定、判断依据、是否需人工复核及建议措施。分类不能确定时允许为空并返回明确状态，不能为了凑齐字段强行猜测。

### 当前已实现与未实现

| 范围 | 当前状态 |
|---|---|
| 本地闭环 | 已实现：Qwen分项/家族 → 有限中文语法提取 → 范围过滤/BM25 → 代码L3/风险 → 解释草稿 → 人工复核 |
| 六类与多问题 | 六类执行器已实现；模型仍有EDC漏检、误分和解释错误，不是六类全正确 |
| 四级规则库接入 | 仅合成六条L3路径及L4参考；未接入真实业务规则库，未实现完整外部文件导入 |
| 规则发布 | 网页只追加PK规则，分类树不可改；其他五类发布、停用/更正/审批、兼容合并尚未实现 |
| 人工与保存 | 后端三角色、逐项修改/确认/退回、版本冲突检测、初判/复核分开保存；非监管电子签名 |
| 预警 | 本地提醒状态与优先级标志；不是抢占调度，无短信/邮件/医院消息投递 |
| 验证 | 18条冻结合成回归保留失败；无真实医院数据、专家独立标签或严格模板隔离泛化结论 |
| M5交付 | 原生启动、分项健康检查、私有备份/隔离恢复工具、技术方案和演示稿；实测范围见M5验证记录 |

## 不在第一版的范围

真实医院系统接入、真实患者数据、诊断/治疗建议、自动决定合规违规、自动处置药物/样本、短信邮件预警、线上公开发布、K8S/vLLM集群、微调、OCR、多Agent自由规划、完整监管认证。
