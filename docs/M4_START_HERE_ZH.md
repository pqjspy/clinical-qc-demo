# M4：一条原文有两个问题，系统怎样分别处理？

这一步继续使用本地网页，不需要先打开Notebook。入口：http://127.0.0.1:8911 。使用原来的reviewer账户；原有规则、记录和复核历史保留。

## 1. 先看一个新问题：访视

在“选择合成案例”中选 `DEMO-VISIT-01`。先读原文，再点击“运行本机 Qwen”。

这条合成记录写了：2026-08-01是第1天，计划第28天访视，实际2026-09-06访视。虚拟方案允许第28天前后7天。

我们要解决的不是“这句话读起来有没有问题”，而是：

1. 这段话属于访视检查，而不是采血、用药或其他检查吗？
2. 研究、方案和日期对应哪一版规则？
3. 实际访视是第几天？Python按日历算出第37天。
4. 允许范围是第21–35天，37超出上界2天。因此提出“访视超窗”的待复核建议。

页面的原文引用、规则引用和计算能让你核对每一步。如果实际运行分错家族或没有解析成功，应看页面的失败/未决原因，不能拿这里的预期讲解当作真实输出。

练习：把起始日改成2026-08-03，实际访视日期不变，另存新记录。现在实际是第35天，恰好在允许范围内。本项未命中仍不代表所有质控检查通过。

## 2. 再看一条原文里的两个问题

选 `DEMO-MULTI-01`，原文同时包含：

| 原文里的事实 | 要检查的问题 | 虚拟规则下的预期建议 |
|---|---|---|
| 同一PK样本10:06采血、10:33开始离心 | 27分钟是否满足至少30分钟 | I1：样本处理时间不足，中风险 |
| 09:00报告恶心；已写原始观察记录；完整AE台账截至12:00仍无对应登记；紧急线索标志为是 | 明确发生的事件是否漏记在指定台账 | I2：AE漏记，高风险 |

“高风险”来自本项目虚拟规则，不是根据“恶心”这个症状作医学诊断。没有提供AE台账，和核对完整台账后明确没有该事件，是两种不同情况。

运行后看右侧两个问题卡。I1和I2各有原文片段、字段、适用规则、程序结果和解释草稿。`[I1-F2]`是第1项的原文证据；`[I2-R1]`是第2项的规则。解释不能拿第1项的引文证明第2项。

总览保留所有问题，显示最高建议风险和未决数。若I1成功而I2缺字段，必须同时显示成功项和未决项，不能把整条记录显示成“正常”。

## 3. 怎样逐项复核和保存

1. 在“本次复核的问题项”选I1，核对原文、程序计算和Qwen解释。
2. 若解释有“27小于30但符合规定”等矛盾，选择“编辑人工意见后保存”，修改的是人工意见，不覆盖AI原文。
3. 写操作理由，勾选核验声明，保存一个新版本。
4. 此时I2尚未处理，整条提醒不能关闭。切到I2再核对、保存。
5. 两项均得到明确的人工意见后才能关闭；任一项退回补充仍显示转交/待处理。
6. 刷新或从人工复核队列重新打开，检查I1/I2的历史都在。复核版本号在整次运行内递增，不是每项重新从v1开始。

模型解释仅做引用结构检查，没有自动验证全部语义。草稿生成失败时，程序计算结果仍可显示，但不能一键确认草稿。整个分项过程失败、一个有效问题项也没有时，只能退回，不能编辑成“AI确认正常”。浏览器验收留下的意见明确标“非临床专业复核”。

## 4. 现在谁负责什么？不是全部交给LLM

```text
完整原文 → 程序切成带位置的片段
         → Qwen按问题分组、选择六个家族之一
         → 程序验证每个片段都被处理
         → 有限中文语法提取明确事实
         → 过滤研究/方案/时点，BM25检索适用虚拟规则
         → Python计算，规则给出L3、风险与建议
         → Qwen组织带引用的解释草稿
         → 每项人工复核，追加保存
```

这是相对原总览的一个明确收窄：M4的字段抽取不是通用LLM抽取，而是我们写的有限语法；L3也由规则确定，不是Qwen独立预测。Qwen确实执行了分项、家族识别和解释；调用、提示词、原始响应与耗时都有保存，没有用预期答案替代失败结果。

`group`是某个家族内部的事件编号，不是句子编号。“采血时间”和“开始离心时间”通常属于同一个PK问题，两句不能各变成一个缺字段的问题。同一原文中的两个不同PK样本则需要不同group。模型在这里仍会犯错。

## 5. 六类到底支持到哪里？

| 家族 | 当前可执行的合成检查 | 不会替你猜的内容 |
|---|---|---|
| PK | 同日、明确北京时间、同一份样本的时间间隔 | 跨日、不同样本、矛盾来源 |
| 访视 | 明确起始日/第1天、目标访视日、实际日，含边界 | 未定义日序、含糊窗口 |
| AE | 明确事件、完整台账范围、登记有/无、紧急线索标志 | 从“没给资料”推断漏记或医学严重性 |
| 用药 | 同批次、同单位、同期间的期初+入库−发放+退回与期末比较 | 把未提供的数量当0 |
| 授权 | 明确人员、操作、完整授权范围和起止日期 | 用今天的授权追认过去操作 |
| EDC | 明确同对象/访视/字段/时点/单位后比较值 | 跨单位、不同时间或不同人直接比较 |

当前最多8个问题项、60个原文片段、8000字。症状、操作、单位、字段名称也有有限词表。新措辞可能被保守地拒绝，这是当前能力边界，不是证明原文没有问题。没有实现其他五类规则的网页发布；发布入口继续只允许追加PK规则。

## 6. 合成评测页怎样读

开发时反复看过的12条展示案例不放进最终分数。另有18条新编记录、21个预期问题项，运行前固定输入、参考、模型和程序版本；真实运行后才加载逐题参考计分。失败保留，不反复重跑挑最好的一次。

- Micro/Macro-F1：检查L3问题有没有找对，不奖励永远输出空结果。
- 完整工作流：更严格，还检查每项状态、风险、优先级和解释流程是否完成。
- 高风险漏检与优先路由分开：转人工并不等于模型分类正确。
- 证据结构有效性：引文是否真的来自对应位置/规则，不等于解释语义必然正确。

18条只是合成回归评测，和展示数据共享作者、规则和有限语法；不是严格模板隔离的泛化测试，也不是医院准确率。评测页列出所有案例的预测/参考和错误，不用一个分数遮住失败。细节见 `data/evaluation/m4_v1/PROTOCOL.md` 和本阶段验证报告。

## 7. 只读这几个代码入口

1. `m4_workflow.py` 的 `analyze_record()`：串起Qwen与程序，记录每个步骤。
2. `m4_engine.py` 的 `parse_facts()`：先只读visit分支，理解字段从哪来。
3. 同文件 `evaluate_issue()`：规则选择与确定性计算。
4. `web_store.py` 的 `review()`：为什么保存I1不能自动关闭I2。
5. `m4_evaluation.py` 的 `score()`：理解失败为何仍在分母。

这些文件都在 `src/clinical_qc_demo/`。不要求一次读完。先做访视案例，再做两问题复核，最后看评测。

命令行也可运行：`.venv/bin/python scripts/run_m4.py --case DEMO-VISIT-01`。命令行读取M1文件规则；网页使用SQLite中已发布规则。两者都会保存真实运行，不混同知识来源。
