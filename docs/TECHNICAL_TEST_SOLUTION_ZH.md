# 临床试验质控问题 AI 自动分类与预警方案

版本：M5 / 2026-09-10。用途：技术方案与原型说明。本项目通过可运行的本地原型验证关键设计，不代表具备医院上线条件。

本文使用“已实现”描述当前代码，“拟接入/后续”描述目标方案。未取得医院真实四级规则库、研究方案或历史QC数据；原型的记录、分类、阈值和风险策略均为合成，不是临床操作标准。

## 一、总体思路

### 1.1 场景理解与目标

质控人员输入的是“待核查的事实描述”，不是已经确认的方案偏离结论。一条记录可能同时包含访视、样本、不良事件、用药、授权和数据一致性问题，也可能只是信息不全。系统目标是降低整理和查找依据的工作量，输出可核对的三级分类与风险建议，并让有权限的人员逐项确认。

以题目QC002为例：同一份样本采血10:06、开始离心10:33；适用的虚拟方案要求至少30分钟。程序计算27分钟，产生“样本管理 / PK样本管理 / 样本处理时间不足”、中风险及“方案偏离”建议。此处30分钟来自题目示例及演示方案，不能推广为一般样本处理要求。是否存在可接受的例外、样本是否可用以及最终是否确认为偏离，仍由相关人员依据完整资料判断。

系统不把“未命中这一条规则”写成“整条记录正常”，也不把“缺少授权/登记材料”写成“已确认没有授权/漏记”。

### 1.2 整体流程与当前分工

```text
原文 + 研究/中心/方案版本/事件时点
  → 保存原文、切成可定位片段
  → 本机Qwen按问题分组，选择问题家族
  → 校验片段覆盖，提取字段及对应原文证据
  → 按适用范围过滤规则，检索候选，检查缺失/冲突
  → Python执行时间、数量、授权及对齐比较
  → 产生L3、风险、建议措施；Qwen生成带引用的解释草稿
  → 分项人工确认/修改/退回；保存初判与修改轨迹
```

当前M4的字段提取是有限中文语法解析，不是通用LLM事实抽取；L3和风险由版本化规则根据已解析事实生成。Qwen分组或家族选择错误仍会造成漏检，不能以“计算是确定性的”掩盖上游模型错误。后续拓展自由文本时，可增加带原文位置的模型候选抽取，但事实对应、范围选择和数值计算仍由代码验证。

所有初判均需人工复核，包括未命中规则的结果。高风险、信息不足、来源矛盾、规则冲突、超范围、模型/解释校验失败应优先处理。当前优先级是工作台标志，不是可抢占的任务调度，也没有向医院、短信或邮箱投递通知。

### 1.3 输出契约

每条记录保留多个问题项，每项至少含：问题编号、一级/二级/三级分类、风险等级、建议判定、判断依据、是否需人工复核、建议措施。另附状态、未决字段、输入证据位置、规则版本、计算过程、L4参考候选和运行编号。

分类明确时，仅接受分类树允许的L3 ID，再回填唯一L1/L2路径，不能让模型自由拼接层级。信息不足时分类可为空，返回“待补充”等明确状态，不为凑齐字段猜测。原始模型草稿与最终人工意见分别保留。

## 二、规则库接入

### 2.1 接入已有四级规则库的方案

拟由业务负责人提供经授权的规则导出及字段字典，先建立稳定分类ID和父子关系，再将源系统字段映射到统一契约。导入步骤为：原始文件留档 → 字段/类型检查 → 父子路径与引用检查 → 版本/适用范围检查 → 业务复核草稿 → 发布不可变快照。发现重名、孤立节点、未知L3或无来源规则时拒绝直接发布。

当前原型仅含六条合成L3合法路径及其L4候选；没有接入真实业务规则库。网页目前只能追加PK规则及其虚拟方案，不能修改分类树，也不能发布其他五类规则。完整的外部Excel/数据库导入适配器、停用、更正及审批流属于后续接入工作。

### 2.2 文字规则如何结构化

规则结构由以下内容组成：

| 字段组 | 含义 | QC002示例 |
|---|---|---|
| 身份和版本 | 稳定ID、版本、发布状态、替代关系 | `SYN-RULE-PK-001@1` |
| 适用范围 | 研究、中心、方案、生效/失效时点 | `SYN-STUDY-001`、方案v1 |
| 必要事实 | 计算前必须齐备的输入 | 同一样本、采血时间、离心时间 |
| 执行条件 | 受支持的检查类型和参数 | `elapsed_minimum`，最小30分钟 |
| 输出策略 | L3、风险、建议、复核要求 | 时间不足、中风险、需复核 |
| 来源 | 文档、章节、准确引文 | 虚拟方案的PK章节 |

不执行从文字或模型生成的任意Python代码。只允许选择已实现的检查类型及经过类型、范围、单位校验的参数。文字规则可由模型辅助整理为草稿，但必须由规则负责人核对来源、边界和适用范围，不能直接发布模型生成规则。

### 2.3 L3、L4、多规则与版本

L3是自动建议目标；L4仅展示该L3下的预配置参考候选，不代表模型完成四级分类。若要进一步自动预测L4，应另行定义标签、数据与评测，不从L3成绩推断L4能力。

不同问题可分别命中不同规则，逐项保留，不能用第一项成功掩盖第二项未决。当前同一问题若存在多条适用规则，不自动合并或挑宽松条款，而是转交复核。目标方案可进一步区分同义重复、独立兼容条件和真正冲突；合并策略必须显式配置并验证，不按检索分数决定规则效力。

规则更新追加新版本，绑定适用方案和有效区间。演示中PK v1最低30分钟，v2自2026-10-01起最低20分钟；同样27分钟在两个适用版本下得到不同结果是版本设计，不是计算矛盾。事件时点用于确定当时有效的规则，不用今天的规则随意回判过去。每次运行保存实际使用的规则快照；新发布不能改写旧初判和旧人工意见。

## 三、AI分类与预警方法

### 3.1 采用混合方案及其原因

选择“本地Qwen + 检索 + 有限事实解析 + 确定性规则 + 人工复核”。Qwen处理问题分组和可读解释；检索提供当前适用规则的来源；代码处理严格边界；人工处理证据完整性和业务判断。

纯规则难覆盖多样自然语言，纯LLM可能计算失误、漏项或生成不存在的分类。直接将整库和原文交给聊天模型能作为实验基线，但不能省略版本筛选、合法分类校验、缺失处理、引用核对、权限与运行留痕。当前小型规则库采用范围过滤后BM25检索，便于观察命中原因；是否增加向量检索、融合排序或重排，应由明确检索失败驱动，不为堆技术提前引入。

本地实现为React工作台、FastAPI、SQLite、Ollama及量化Qwen3-4B。采用单个模型工作线程，避免多任务争用本机资源。没有训练或微调Qwen；量化版本由模型发行包提供，不宣称自己完成了模型压缩训练。

### 3.2 六类检查如何落地

| 家族 | 当前明确事实和检查 | 必须避免的错误 |
|---|---|---|
| 样本 | 同一样本的采血/开始离心时间，比较最小间隔 | 用提交时点补缺失时间 |
| 访视 | 锚点、实际日期、Day 1定义，计算闭区间窗口 | 日号与自然日差混用 |
| AE记录 | 事件明确存在、指定登记台账已完整核对、对应条目缺失 | 没有提供台账就判漏记 |
| 试验用药 | 同批次、期间、单位下的期初、入库、发放、可用退回、实盘 | 缺失数量当0 |
| 授权 | 操作人、操作、完整授权清单及有效区间 | 未提供授权材料就判无授权 |
| 原始记录/EDC | 主体、字段、时点和单位对齐后比较值 | 把不同时点或单位的数据直接比较 |

当前对中文句式、可识别症状、操作名和单位有明确限制；无法解析时保留未决，不自动通过。这六类执行器的存在，不代表模型六类全部识别正确。

### 3.3 风险、依据、建议与多问题处理

风险等级来自已确认规则策略，而不是LLM自由判断严重程度。演示中的“紧急线索标志”仅影响优先人工处理，不是依据症状做医学分级。总体展示保留最高已识别风险和未决项；即使没有高风险标签，信息不足也不能按低风险处理。

每项依据同时包含输入片段F、规则来源R、时间/数量计算。多问题时采用`I1-F1`、`I2-R1`等独立编号，避免引用串项。程序验证位置、引文、规则适用性及引用ID；这些验证并不证明LLM解释的每一句语义都正确。已观察到“27分钟小于30分钟”后又写“符合要求”的草稿错误，必须让复核人修改人工解释，不能靠有效引用ID掩盖矛盾。

对缺失/模糊记录返回具体未决字段；对矛盾来源保留各自位置；对超范围返回“不支持”；对多问题要求所有业务片段都被处理。输入中的“忽略规则”等语句作为待分析数据，不授予模型修改规则或执行工具的权限。所有失败与未决必须进入记录和评测分母。

## 四、人工复核与合规控制

### 4.1 角色与操作闭环

查看者只能阅读；复核者可创建记录、分析和逐项确认/修改/退回；规则管理员可创建和发布规则草稿，不代替复核者签署意见。权限由后端检查，不仅隐藏按钮。

复核时展示原文、适用规则、计算和AI草稿。修改必须选择合法L3及一致的状态/风险/建议，填写理由并确认已核对依据。提交带预期版本和请求编号，防止重复分析/复核请求与旧版本覆盖。逐项保存后，只有全部问题项处理完成，记录的提醒才可关闭；退回补充不等于已解决。另存原文产生新记录，不覆盖旧原文。

运行快照保留输入摘要、模型身份、提示词版本、知识库版本、步骤耗时、模型响应和初判。人工事件记录操作人、时间、修改原因、修改后的意见及版本。人工修改不回写原始AI结果；旧模型、旧规则的历史不会随新版本变化。

### 4.2 不替代最终判断

原型全部结果是待复核建议，不自动确定医学诊断、治疗措施、临床严重性或最终合规状态，不自动丢弃样本或更正EDC。样本是否接受、偏离是否成立等问题需有权限人员结合完整方案、来源材料和实际情况决定。规则初判与模型解释应分栏，解释失败不能把已识别的高风险线索清除。

### 4.3 隐私与安全边界

当前仅使用显式合成记录和SYN编号。应用绑定127.0.0.1:8911，模型绑定本机11434；不调用云模型、不自动回退到外部服务。应用使用会话Cookie、Origin/CSRF检查、请求大小限制、后端权限和密码哈希。模型请求禁用代理和重定向，前端静态资源在本地提供。

这些措施不等于生产安全认证。本机账号初始化文件保存明文演示密码；数据库和备份未加密，主机管理员仍能修改文件。追加表和哈希能帮助发现普通误改，不是监管级防篡改或合规电子签名。备份包含密码和原文，必须留在私有目录，不能作为公开投递附件。

真实接入前需由医院确认数据授权、最小化字段、去标识方式、角色范围、保留/删除期限、加密与密钥管理、访问审计、备份恢复及事件处置。部署到多人网络时，还需受控认证、传输安全、访问控制和运维审查；不能把本机演示直接改为监听所有网卡后当作院内上线。

## 五、实施与验证计划

### 5.1 分阶段落地

| 阶段 | 交付物 | 验收关注点 |
|---|---|---|
| 需求与规则梳理 | 输出契约、分类映射、业务边界、QC002故事 | 输入不是答案，规则来源明确 |
| 合成数据与单项闭环 | 展示案例、独立参考、版本化规则、本地Qwen调用 | 真实推理、27分钟计算、缺失不猜测 |
| 工作台与人工复核 | 网页、角色、数据库、证据、追加历史 | 修改后可重开，越权被拒绝 |
| 六类与多问题 | 有限语法执行器、分项复核、冻结18条回归 | 漏项、误分、引用失败均计入 |
| 本地交付 | 启动/状态检查、私有备份、隔离恢复演练、方案/演示稿 | 保留用户记录；明确安装/离线验证范围 |
| 后续真实验证 | 授权数据、专家标注、影子运行与受控试点 | 经业务负责人确认门槛后再扩大使用 |

前四阶段已有可运行实现；M5交付证据见独立验证报告。未做医院数据接入、模型微调、OCR、多模态、K8S或vLLM生产部署。

### 5.2 历史质控记录如何评测

取得授权后，收集历史原文、上下文及事件当时有效的规则版本。由至少两名具备相应业务资格的人员独立标注问题项、L3、风险、依据、信息充分性与是否应转交；分歧仲裁，冻结标注指南。历史系统的分类仅作参考，不能默认无误。

按研究、中心、时间与同一事件分组切分，检查相同受试者记录、重复文本及模板的跨集合泄漏。开发集用于提示词/规则修改，验证集用于选择版本，测试集冻结后只做约定评估；另设时间或研究外部验证。规则知识可供检索，逐题参考答案不得放入模型输入。真实测试规模依据类别频率和精度要求设计，而不是沿用18条。

分别报告问题级多标签Micro/Macro-F1、逐类支持度和召回率、整条多问题完整率、高风险漏检率、已检出后的风险低估率、转交召回与不必要转交率、未决率、模型失败率，以及解释语义正确性。专家另行判断“解释是否真正由所引证据支持”。高风险和小样本指标应报告分母及置信区间，不能只报百分比。

### 5.3 已完成的合成评测，不隐去错误

冻结M4首次运行使用18条新合成记录，含21个问题项、12个阳性问题和4个高风险问题，与12条展示案例分开。模型是本机Qwen3-4B量化版，无微调。该18条仍共享作者、规则及有限语法，不是严格模板隔离的泛化测试。

| 指标 | 结果及含义 |
|---|---|
| 问题级Micro-F1 / Macro-F1 | 0.9091 / 0.8333 |
| 阳性问题召回 | 10/12；EDC两条均漏检 |
| 预定义完整工作流一致 | 13/18，不是解释语义正确率 |
| 多问题项完整 | 2/3条记录 |
| 高风险问题漏检 / 风险低估 | 0/4、0/4；只有4个合成问题，不能承诺零漏报 |
| 不必要优先转交 | 3/9条原本不需优先的记录 |
| 解释引用校验失败 | 2/18；保留实际规则结果与错误 |
| 证据结构有效 | 134/134；不等于每句解释都真实正确 |
| 18条尝试的平均耗时 | 10.31秒，含未决与解释失败；仅本次环境/样本，非p95或生产SLA |

例如EDC的访视信息被误分入“访视”家族，使EDC检查缺字段；另有解释引用了不存在的编号。后续修复必须建立新提示词/数据/评测版本，保留本轮结果，不能覆盖后声称首轮即达到新成绩。

### 5.4 高风险漏报控制与上线门槛

高风险标签漏检、风险低估和未转交应分别追踪：正确转交不代表正确分类，分类正确也不保证提醒及时到达。对高风险线索、未决、冲突及系统失败，采取保守人工转交；同时监测误报工作量，避免通过“全部高风险”虚增召回。

后续以离线评测 → 不影响业务的影子运行 → 双人复核/抽审 → 受控试点推进。业务与安全负责人共同约定可接受的漏报上限、置信区间、误报量和响应时间；现阶段不擅自承诺某个医院准确率。模型、提示词、规则或字段解析更新都需要回归和版本记录；发现严重漏报时暂停相关自动建议、保留人工路径并回退到已验证版本。
