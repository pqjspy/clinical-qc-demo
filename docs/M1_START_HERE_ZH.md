# M1 从这里读：我们现在手里到底有什么？

**现在已经有可读取的虚拟数据和检查代码，还没有接入Qwen，也没有网页。**

你先只看QC002，不必一开始读完所有JSON和Python类。

## 1. 第一份东西：用户交给系统的事实

这是 `data/inputs/cases.json` 里QC002的真实内容（真实指这个文件确实有这条记录，病例本身完全虚构）：

> 【合成虚拟记录】2026-09-01，SYN-SUBJ-002同一份PK样本的采血时间为10:06，开始离心时间为10:33，均为北京时间。请检查样本处理是否符合本研究方案。

**这里没告诉系统答案。** 没有给“中风险”，没有给“样本处理时间不足”，也没有说至少30分钟。

另有研究编号、中心、方案版本与日期等上下文，让系统知道应查哪套要求。SYN开头表示虚构标识，不是真实受试者或医院编号。

## 2. 第二份东西：系统可以查阅的要求

在独立的虚拟方案里，我们写了：

> 本虚拟研究规定，同一PK样本从采血到开始离心的时间间隔至少为30分钟。

这不是用户记录，也不是逐题答案。它是对这个虚拟研究的所有适用样本都生效的规则；27、30、40分钟都应根据同一条要求判断。

同一规则还写明：不足时采用哪个L3、什么建议风险、是否需复核。它来自题目QC002样例的演示设定，不是通用医学要求。

分类树则单独规定，`L3-PK-001` 对应：

**样本管理 → PK 样本管理 → 样本处理时间不足。**

## 3. 第三份东西：我们写给测试程序的参考答案

`data/reference/expected_results.json` 中为QC002写了预期：

- 时间间隔应是27分钟，小于虚拟要求的30分钟。
- 应提出上述三级分类，中风险，建议方案偏离，需人工复核。
- 依据应指向记录中的两个时间，以及对应版本的规则原文。

**参考答案不能发给Qwen。** 下一步要让Qwen看到第一份输入，以及检索到的第二份知识；第三份只用来检查它答得对不对。

当前预览工具会读取第三份，所以显著显示 `fixture_preview` / “预期答案预览”。它不是一个假装已经完成的AI系统。

## 4. 文件分别有什么用

| 你要看什么 | 文件 | 一条记录代表什么 |
|---|---|---|
| 用户原文 | [cases.json](../data/inputs/cases.json) | 一个虚拟QC记录，共12条 |
| 允许的分类 | [taxonomy.json](../data/knowledge/taxonomy.json) | 一个合法L1→L2→L3路径，共6条，L4另作候选 |
| 可引用的原文 | [protocols.json](../data/knowledge/protocols.json) | 一份虚拟方案，共3份，内部有段落 |
| 机器可读条件 | [rules.json](../data/knowledge/rules.json) | 一条具体版本的规则，共9条 |
| 测试参考 | [expected_results.json](../data/reference/expected_results.json) | 对一条输入的预期处理结果，共12条 |

为什么12条输入只有8个预期问题项？六条单问题各1项，加一条多问题有2项，共8项。剩下5条是边界通过、缺信息、规则冲突、超范围和事实矛盾，不能都强行贴一个违规标签。

为什么6种分类有9条规则？正常v1六条 + PK更新v2一条 + 独立冲突研究两条。v2只演示PK更新，不表示另外五类在v2已经有规则。

## 5. 亲手运行QC002

在项目目录终端运行：

```bash
.venv/bin/python scripts/validate_m1.py --case QC002 --readable
```

输出依次是用户原文、预期状态、分类和规则证据、原因、算术核对。这里代码复算的是**我们预先给定的时间参数**，不是已经从原文自动抽取了时间；自动抽取是M2的工作。

然后看两个不同结果：

```bash
.venv/bin/python scripts/validate_m1.py --case DEMO-BOUNDARY-01 --readable
.venv/bin/python scripts/validate_m1.py --case DEMO-MISSING-01 --readable
```

- `DEMO-BOUNDARY-01`：开始离心时间10:36，正好30分钟，不命中“时间不足”。没有违规分类，不等于整个试验合规。
- `DEMO-MISSING-01`：没有开始离心时间。12:00只是提交时间，不能拿来替代，所以应要求补充。

**先思考：为什么这两条都没有L3，但并不是同一种结果？** 前者是这一条检查未发现问题，后者是缺证据、还不能判断。

## 6. 其余案例看什么

| 案例 | 原文中的关键事实 | 预期行为 |
|---|---|---|
| DEMO-VISIT-01 | 8月1日算第1天，9月6日实际访视 | 第37天，超出虚拟第21-35天窗口 |
| DEMO-AE-01 | 原始记录有事件，完整核对登记册后确认没有相应条目 | AE漏记建议；按虚拟策略优先复核 |
| DEMO-DRUG-01 | 100+20-15+5，实盘108 | 应有110，与实盘不同；不推断差异原因 |
| DEMO-ROLE-01 | 授权于当天00:00结束，09:00才操作 | 超出授权时段，需复核 |
| DEMO-EDC-01 | 同主体/字段/时点/单位，37.2与38.2 | 提示不一致，不选一方当真、不诊断 |
| DEMO-MULTI-01 | PK时间不足，同时AE登记缺失 | 保留两项，不能漏掉高优先级AE项 |
| DEMO-CONFLICT-01 | 27分钟，但同范围两条规则分别要求30和20 | 报规则冲突，不挑有利的一条 |
| DEMO-UNKNOWN-01 | 办公打印机无线网络故障 | 超出当前六类范围，不发明L3 |
| DEMO-AMBIGUOUS-01 | 纸质记录10:33，离心台账10:36，两者均未作废 | 保留矛盾来源，先核实事实 |

上表是阅读导航；完整原文在输入文件，独立预期在参考文件。`高风险`只是本Demo明示的提醒策略，不能当作真实医学严重程度。

## 7. 当前代码验证了什么？

```bash
.venv/bin/python scripts/validate_m1.py
.venv/bin/python -m unittest discover -s tests -v
```

检查包括：数据字段是否合法、ID是否重复、分类是否存在、规则与方案范围是否匹配、引文是否逐字存在、版本日期是否正确、参考算术能否复算、模型输入投影是否不含答案和场景ID。

没有测到：Qwen能否理解原文、抽取是否正确、检索是否命中、实际分类准确率、网页/人工审核是否可用。这些留在下一阶段实现，不用本阶段的通过数冒充模型成绩。

实现代码按阅读顺序：先看 [validate_m1.py](../scripts/validate_m1.py) 的入口，再看 [data.py](../src/clinical_qc_demo/data.py) 的 `build_model_input` 和 `preview_case`；需要时再看 [contracts.py](../src/clinical_qc_demo/contracts.py) 的字段约定。

下一步M2：让本机Qwen真正从QC002原文提取两个时间，检索对应规则，调用计算，再生成可追溯的待复核建议。不能根据QC002编号直接取参考答案。
