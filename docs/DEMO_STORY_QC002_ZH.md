# 第一条演示故事：QC002

这是一份开发前的输入/输出约定，不是已运行结果。案例取自测试样例并补充明确标记的虚拟上下文。

## 用户输入

研究：`SYN-STUDY-001`；虚拟中心：`SYN-SITE-A`；虚拟受试者：`SYN-SUBJ-002`。

选择的方案版本：`SYN-PROTOCOL-001-v1`。这些 ID 与 2026-09-01 日期是我们为演示合成的，原题未提供。

> 2026-09-01，同一份PK样本的采血时间为10:06，开始离心时间为10:33，均为北京时间。请检查样本处理是否符合本研究方案。

用户输入不含预期 L3、风险或参考答案。后台评测答案不传给模型。

## 系统可检索的独立虚拟规则

规则 ID：`SYN-RULE-PK-001`；规则版本：`1`。

> 本虚拟研究规定，同一PK样本从采血到开始离心的时间间隔至少为30分钟。小于30分钟时，提示“样本处理时间不足”，建议风险为中，建议判定为方案偏离，须人工复核。

规则发布时绑定：样本管理 → PK 样本管理 → 样本处理时间不足。

来源位置：虚拟方案 `SYN-PROTOCOL-001-v1` 的“PK样本处理”段落。L4可设置一个独立候选，但不自动确认。此规则是按原题样例搭建的虚拟配置，不是一般临床操作指引。

## 系统需要真实执行的五件事

1. Qwen 从原文抽取样本、采血/开始离心时间、日期和时区，保留对应原文片段。
2. 检索器按研究和版本找到适用规则，展示规则原文；不是用 QC002 编号查答案。
3. Python 算 `10:33 - 10:06 = 27分钟`，比较 `27 < 30`。
4. 结果校验器核对合法路径、来源、计算与建议风险；Qwen只能基于这些证据组织解释。
5. 用户看到待复核结果，能确认或修改，审计中保留原始 AI 初判和人工动作。

上述是设计预期，不是模型输出。实际实现还需附加问题ID、结构化事实、原记录证据位置、规则ID/版本/引文、计算过程、模型版本、运行ID和审核状态。

## 页面上的人工动作

- “确认建议”：生成一条人工确认事件，而不是直接覆盖 AI 结果。
- “修改并确认”：例如复核者认为风险应调整，须填写理由；修改前后都保留。
- “退回补充”：发现时间来源不明确时转待补充，不能自动关闭为无问题。

## 你会亲手改的四个输入

| 改动 | 应观察到什么 |
|---|---|
| 离心改成10:36 | 恰好30分钟，不应命中“不足30分钟”；不代表该记录所有事项均合规 |
| 删掉离心时间 | 需补充信息，不能默认时间为0或自动通过 |
| 另提供台账离心为10:36，原记录仍为10:33 | 明确显示来源矛盾，不能静默挑有利时间 |
| 换成另一个研究，但未提供该研究的有效规则 | 不能套用本研究30分钟规则，应提示适用规则不足 |

跨午夜、多问题、高风险、版本冲突等变体随后加入。先把这一条真实跑通，比先生成几千条难以解释的记录更有价值。
