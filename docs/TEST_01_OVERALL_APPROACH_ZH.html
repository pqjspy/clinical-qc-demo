临床试验质控记录自动分类与风险预警方案

技术方案答卷

总体思路 · 规则库接入 · AI分类与预警方法 · 人工复核与合规控制 · 实施与验证计划

一、总体思路

本方案将系统定位为临床试验质控人员的辅助工作台，采用“大语言模型理解文本、规则库提供依据、程序完成校验、人工确认结论”的混合方式。系统自动生成第三级分类、风险等级及处理建议，但不代替最终医学或合规判断。

1. 如何理解临床试验质控记录自动分类场景？

临床试验质控记录是对检查中发现情况的文字描述，如访视超窗、AE漏记、样本处理异常等。一条记录可能包含多个问题，也可能信息不足，不能直接视为已确认违规。

系统需要结合研究方案和适用规则，逐项给出三级分类、风险等级及判断依据，减少人工查阅和整理工作，提高分类一致性，并帮助优先处理高风险和不确定事项。系统输出是待复核建议，最终结论由有权限的人员确认。

2. 系统整体流程是什么？

拟采用以下流程：

输入质控原文及研究上下文
        ↓
识别问题、整理关键事实与原文证据
        ↓
筛选事件时点适用规则，混合检索并按需重排
        ↓
校验事实、执行计算，形成逐项分类和风险建议
        ↓
展示判断依据、未决信息及复核提醒
        ↓
人工确认、修改或退回补充
        ↓
保存初判、最终意见及完整修改记录

各环节的处理内容如下：

  1. 接收并保存输入。 保留质控原文，同时关联研究编号、中心、方案版本和事件发生时间。只使用经授权且必要的数据；缺少影响判断的上下文时要求补充，不擅自填入默认值。

  2. 识别问题与事实。 从文本中识别一个或多个问题，整理人员、样本、日期、时间、数量及相关记录等信息，并保留对应的原文位置。系统应检查是否存在未处理片段，但片段全部被分配不代表模型已经理解正确。

  3. 查找适用规则。 在用户权限内，先按研究、中心、方案版本和有效时间筛选，再结合BM25关键词检索与Dense向量检索，以RRF融合两路排名，按需使用Cross-Encoder重排候选条款。相关性排名不能替代规则适用性判断，不能用其他研究或今天的新规则判断过去的事件。

  4. 校验并形成初判。 对时间间隔、访视窗口、库存数量等可明确计算的条件，由程序执行；结合合法分类路径和风险策略，为每个问题生成分类、风险及建议判定。

  5. 展示结果与提醒。 同时展示原文证据、规则来源、计算过程、建议措施及是否需人工复核。高风险、信息不足、规则冲突或系统失败分别标记，不能静默变成“无问题”。

  6. 人工复核并留痕。 复核人员可确认、修改或退回补充。保存原始输入、系统初判、适用规则版本、人工意见、修改理由、操作人和时间，不用最终结果覆盖初判。

对于多问题记录，每项均保留自己的分类、依据和复核状态。一项处理完成，不代表整条记录的其他问题也已解决。

3. AI如何辅助完成三级分类和风险预警？

3.1 辅助三级分类

大语言模型负责理解不同表述、识别问题主题、拆分多个问题，并提出候选分类或关键事实。系统再结合已有规则库进行核对，而不是让模型任意创造分类名称。

分类结果必须属于规则库允许的第三级节点。确定合法的三级分类后，系统根据分类树回填对应的一级和二级分类，避免出现层级不一致。第四级分类仅作为人工参考或后续扩展，不作为本次自动输出目标。

对于“时间间隔不足”等能够明确形式化的问题，由校验后的事实和规则条件确定三级分类；对于尚不能可靠判断的问题，保留候选或返回“待补充／待人工判定”，不强行给出确定结论。

例如，沿用QC002的设定：同一份PK样本10:06采血、10:33开始离心，且已确认适用方案要求间隔至少30分钟。本方案拟按以下流程处理：

  1. AI识别问题并提出事实： Qwen识别PK样本处理问题，提取采血、离心时间等候选事实并关联原文；程序核对事实来源、同一样本、日期和时区。问题家族作为检索线索，不用于直接排除其他可能相关的类别。

  2. 筛选适用范围： 在用户有权访问的规则中，按研究、中心、方案版本和事件时间筛选，排除不适用的规则。

  3. 混合检索候选规则： BM25根据“PK”“采血”“离心”等词匹配条款；Dense向量检索补充措辞不同但语义相关的条款，例如“开始离心”与“启动离心处理”的表述。两路结果按规则ID及版本合并，保留各自证据片段，以RRF融合排名，形成候选列表，而不是只选BM25排名第一的规则。

  4. 按需重排并补全关联： 使用Cross-Encoder将问题描述与候选条款成对比较，优先排列更相关的内容；候选数量及是否启用重排通过评测确定。必要的关联规则、例外和冲突检查不受排名前几条的限制。

  5. 程序判断条件并确定三级分类： 核对相关规则的条件及例外后，程序计算出27分钟，小于适用阈值30分钟，命中“时间不足”条件，取得规则关联的三级分类ID L3-PK-001。多规则按重复、互补或不同问题分别处理；无适用依据、事实不足或冲突无法消解时保留未决状态，不凭检索或重排得分强选结论。

  6. 程序回填上级分类： 根据这个ID查分类树，取出固定路径：样本管理（一级）→ PK样本管理（二级）→ 样本处理时间不足（三级）。

BM25、Dense、RRF和重排负责查找及排列相关依据，不负责判断27 < 30，其得分也不是风险或分类置信度。一级和二级分类由程序查表得到，不需要AI分别生成。此处30分钟来自题目设定，不是通用临床标准。

3.2 辅助风险分级与预警

风险等级应依据经业务负责人确认的风险规则及具体事实产生，而不是让模型仅凭语气或关键词自由判断。例如，不能仅看到“不良事件”几个字，就自动认定为严重或高风险事件。

拟将“风险等级”和“处理优先级”分开：

  • 风险等级描述已有证据支持的问题风险，按规则产生低、中、高等建议等级。

  • 处理优先级决定哪些记录需要尽快由人工查看。高风险问题，以及事实不足、规则冲突、无法分类或模型失败的记录，可进入优先复核范围。

信息不足时，风险应标为“待定”，不能自动降为低风险；优先复核也不等于已经确认高风险。多问题记录应逐项展示风险，并在汇总处突出最高已识别风险和仍未解决的问题，避免用平均值掩盖高风险事项。

预警应同时说明“为什么提醒、依据在哪里、建议下一步核查什么”。大语言模型可将经过校验的结果整理为带引用的解释草稿，但不能改变计算结果、规则阈值或已确认的适用版本。引用位置正确也不等于解释语义正确，复核人员仍需检查解释是否与事实一致。

3.3 用题目中的QC002说明

沿用题目示例：在已确认属于同一样本、时间记载可靠且方案适用的前提下，采血时间为10:06，离心时间为10:33，规则要求间隔至少30分钟。

程序计算得到：10:33 - 10:06 = 27分钟，且27 < 30。系统形成以下初判：

输出字段 示例结果
一级分类 样本管理
二级分类 PK样本管理
三级分类 样本处理时间不足
风险等级 中
建议判定 方案偏离，待人工确认
判断依据 两个时间的原文证据、适用方案条款及27分钟的计算结果
是否需人工复核 是
建议措施 由负责人员确认样本是否被中心实验室接受，并评估检测结果是否有效

这里的“至少30分钟”和“中风险”来自本题示例设定，不是通用临床标准。AI的作用是帮助识别问题、查找依据和整理建议；它不能仅凭该记录决定样本无效，或者代替人员完成最终偏离认定。

4. 哪些内容仍需人工复核？

采用“初期全量复核、验证后分级自动化”的策略。前述人工确认流程用于初期落地；后续可对满足条件的具体任务免除逐条复核，但仍保留人工监督。

4.1 初期：所有初判均需复核

复核人员核查事实与原文是否一致、规则版本是否适用、是否遗漏问题，以及分类、风险和解释是否合理。“本项未触发异常条件”也需核查，防止漏报；“未找到适用规则”则属于未决状态，不能当作检查通过。

4.2 验证后：部分任务自动处理，人工抽查

经业务及质控负责人批准的低风险、边界明确任务，可从逐条复核改为人工抽查，前提是：

  • 依据可靠： 事实完整可追溯，研究、方案版本及事件时间匹配，适用规则无冲突。

  • 验证达标： 用有独立人工参考的代表性真实业务数据验证，并开展人机并行试运行；拟自动处理任务的错误放行、漏报等指标须达到预定标准，不能只看总体F1或模型自报置信度。

  • 人工兜底： 保留依据与日志，持续抽查；异常或超范围转人工，模型、规则或数据来源变更后重新评估。

例如，已核实时间算出40分钟，满足适用的合成规则“至少30分钟”，仅代表该项检查通过，不代表样本整体合格。

4.3 保留人工复核的事项

符合4.2条件的任务可自动处理；未纳入验证及授权范围的任务仍需逐条复核。以下两类事项保留人工介入：

  • 无法可靠判断的情况： 事实缺失或矛盾、规则冲突或例外、未知问题类型、模型或程序失败时，转人工补充信息和核查。AI生成的判定理由（对分类及风险等级的文字说明）与原文、规则或计算结果不一致，或无法可靠核验时，也归入此类。

    例子： 同一份PK样本于同日10:06采血，但原始记录写10:33开始离心，电子记录写10:46开始离心。两种记载分别对应27分钟和40分钟；若该研究方案规定间隔至少30分钟，将产生不同的检查结论。系统应标记来源冲突，由人工核实正确时间后再判断，不能自行挑选一个时间。

  • 高风险事项及需专业确认的决定： 对受试者安全或数据可靠性有潜在重大影响的事项，以及规则尚未覆盖或未获准自动处理的专业判断与处置，由具备相应权限和业务资格的人员确认。疑似高风险可先自动预警，不必等待最终认定。

    例子： 假设某条质控记录写明“受试者在使用试验药物后突发不适并住院”，且已批准的规则要求此类记录立即预警，系统可自动标记并通知负责人员。但“不适是否由试验药物引起、后续如何处置”，仍需研究医生结合病史、合并用药和检查结果评估，不能仅凭“用药后发生”认定“由药物导致”。这里人工负责医学评估，而不是重复确认系统是否命中了预警规则。

复核人员可逐项确认、修改或退回补充，并记录理由。自动处理与人工复核均保留原文、系统初判、适用规则版本及处理记录；一项通过不代表整条多问题记录可以关闭。

二、规则库接入

拟将已有规则库整理为两个关联部分：分类树规定“可以分到哪些类别”，判断规则规定“什么条件下归入该类别，以及如何分级和处理”。两者通过分类ID关联，保留原有业务含义，不让AI自行重建分类标准。

1. 如何接入已有四级分类规则库？

  1. 取得数据并映射字段。 根据现有载体，通过Excel、JSON、数据库或接口导入，保留原始文件与原系统编号。将不同字段名称统一映射为分类ID、名称、层级、父节点ID、定义、适用范围、来源及版本等字段。

  2. 建立分类树与规则关联。 分类节点保存上下级关系、定义及必要的同义表述；判断规则单独保存，关联目标三级分类ID和原文条款。如果原规则关联在第四级，系统就找到该第四级所属的第三级，作为自动分类的输出；同时保留原第四级关联供查看。如果规则本来就关联第三级，则直接使用。名称相同但上级不同的节点不能直接合并，不能仅靠名称作为唯一标识。

  3. 检查后审核发布。 程序检查重复ID、缺失父节点、错误层级、循环关系，以及规则引用的分类是否存在。歧义由规则负责人确认后处理；审核通过的版本再写入规则库并建立关键词索引和向量索引，保留规则ID、版本及原文位置，草稿不参与正式判定。

例如，若原库提供“样本管理 → PK样本管理 → 样本处理时间不足 → 采血至开始离心间隔不足”，系统保留这条四级路径，再把相应判断规则关联到“样本处理时间不足”的三级ID。

2. 如何将文字规则转为系统可用的结构化规则？

先将一段文字拆成“适用范围、必要事实、判断条件、输出及例外”。AI可辅助生成结构化草稿，程序检查字段和逻辑，规则负责人核对原文与业务含义，再通过边界用例验证后发布。

字段组 需要保存的内容
规则身份 规则ID、版本、草稿／已发布／停用状态
适用范围 研究、中心、方案版本、生效及失效时点
必要事实 所需字段、类型、单位、来源要求，如同一样本及两个完整时间
判断条件 检查类型、比较方向、阈值、是否包含边界、例外及信息缺失处理
输出策略 目标三级ID、风险等级、建议判定、建议措施及复核策略
来源与审批 原文引文、文档及章节、审批人、审批时间及替代关系

例子： 假设某研究方案规定“同一PK样本从采血到开始离心至少间隔30分钟”，可将核心条件表示为：

{
  "check_type": "elapsed_minimum",
  "required_facts": ["same_sample", "collected_at", "centrifuged_at"],
  "parameters": {"minimum_minutes": 30},
  "output_l3_id": "L3-PK-001"
}

其中，elapsed_minimum对应程序预先实现的“最小时间间隔检查”。确认同一样本、日期与时区明确、时间顺序正确且来源无冲突后，程序计算间隔：小于30分钟命中“样本处理时间不足”；恰好30分钟不命中该项异常。缺少时间、时间倒置或存在冲突时返回待核查，不当作检查通过。

这个片段仅展示判断核心，完整规则还需包含上表中的适用范围、来源和输出策略。风险、业务判定及例外处理不能从“至少30分钟”一句话中自行推导，须由规则负责人补充确认。程序只执行预先支持的检查类型，不执行AI临时生成的任意代码；含义不明确的条款先作为参考材料，不直接用于自动判定。

发布前至少测试29、30、31分钟，以及时间缺失、来源矛盾和例外场景，确认比较方向、边界和未决状态均符合规则原意。

3. 如何支持自动分类到第三级？

  1. 定位问题和候选规则。 AI识别记录中的问题，整理相关事实；程序在用户权限内，先按研究、中心、方案版本和事件时间筛选，再结合BM25关键词检索与Dense向量检索，通过RRF融合排名，按需使用Cross-Encoder重排。检索匹配只表示相关，不代表已经满足规则条件；必要的关联、例外及冲突检查不能因候选排名靠后而省略。

  2. 核对条件并确定三级ID。 可明确计算的问题由规则程序判定，命中后读取规则关联的三级ID；需要文本理解的问题可由AI在已有三级候选中提出建议，并保留证据。无法确认的情况返回候选或待核查，不强行分类。

  3. 校验合法路径并回填上级。 检查三级ID是否存在于本次使用的分类树版本及允许范围内，再通过父节点关系取得一级和二级分类。模型不能自由生成或拼接分类名称。

例如，程序确认“间隔27分钟，小于适用阈值30分钟”后，读取规则的output_l3_id = L3-PK-001，查表得到“样本管理 → PK样本管理 → 样本处理时间不足”。条件核验与分类合法性检查各有作用：前者确认事实是否满足规则，后者保证输出属于已有分类体系。

一条记录含多个问题时，逐项输出三级分类、证据及处理状态，不限制整条记录只能选一个类别。是否需要逐条人工确认，沿用第一部分第4节的验证与授权策略。

4. 第四级分类如何作为参考信息或后续扩展？

当前自动分类目标止于第三级，但导入时保留第四级节点及其定义、父节点和关联条款。确定三级分类后，可在界面展示其下的第四级候选，帮助复核人员了解具体情形；候选展示不等于已确认第四级分类。

例如，三级为“样本处理时间不足”时，可展示其下“采血至开始离心间隔不足”的定义和依据。证据不足时允许第四级为空，不为了补齐层级强选一个节点；人工选择第四级后，应单独记录，并检查其确实属于当前三级节点。

后续若扩展第四级自动分类，应先确认各节点的区别和标注标准，积累对应标注数据，单独评测并批准后启用。三级分类的成绩不能直接代表第四级能力；新增第四级字段也不应改写既有三级结果。

5. 如何处理多规则命中、规则冲突和规则更新？

5.1 多规则命中：区分重复、互补和不同问题

拟按下列方式处理，而不是一律取检索排名第一的规则：

情况 处理方式
不同问题分别命中规则 分项保留，例如同一记录同时有样本处理异常和AE漏记
同一问题、同一三级结果的重复依据 按问题和分类合并展示，保留全部规则引用，不重复生成相同提醒
同一问题存在互补条件 分别执行并按已批准的组合策略汇总，例如同时检查最小间隔和最大间隔
对同一事实给出不相容要求或结论 按冲突流程处理，不直接合并或自动选一条

风险或建议措施不一致时，须按明确的业务策略处理，不能因为三级分类相同就忽略差异。问题级风险和未决状态分别保留，不用平均风险掩盖高风险事项。

5.2 规则冲突：先检查适用性，再核对规则关系

先排除研究、中心、方案版本或事件时间不匹配的规则。若仍有重叠，检查经批准的替代、优先或例外关系；无法消解时标记冲突，展示相关原文并转规则负责人处理，不输出确定结论。检索分数、版本号大小或“自动取最严”均不能代替适用性判断。

例如，同一研究、方案和有效期内，对同一种样本、同一时间间隔，一条要求“至少30分钟”，另一条要求“不超过20分钟”，且没有例外说明，两项要求无法同时满足，应核查规则配置。若它们分别属于不同研究或不同有效期，则不因数值不同就视为冲突。

5.3 规则更新：发布新版本，保留历史依据

更新按“修改草稿 → 业务审核 → 回归测试 → 发布新版本”执行，明确适用方案、生效区间及替代关系。有效区间统一包含起点、不包含终点，并注明时区，避免版本交界重复生效。规则内容和分类树分别记录版本；若分类节点拆分、合并或停用，保存新旧ID映射及对应规则调整，不直接覆盖历史分类。

例如，某研究方案v1要求间隔至少30分钟，v2从10月1日起改为至少20分钟。在研究、中心、方案版本均匹配的前提下，按事件时点选择当时有效的规则：同样27分钟，9月适用v1时不足，10月适用v2时不触发该项异常。不能只看上传时间，也不能只因当前版本较新就用于过去事件。

每次分析固定使用的规则与分类树版本，并保存依据快照。发布时同步更新关键词索引和向量索引，按同一发布版本切换，避免检索旧规则、执行新规则；测试不通过不发布。向量模型、重排模型及检索配置也记录版本；更换向量模型时重建对应索引，确保查询和规则向量采用匹配的编码方式。历史记录需要复算时另存新结果和差异，不覆盖旧初判及人工意见。规则或检索组件变更后，重新评估受影响任务的自动处理资格。

三、AI分类与预警方法

1. 采用规则引擎、大语言模型、NLP模型、RAG或混合方案？

拟采用“本地大语言模型理解文本、混合检索提供依据、规则引擎执行判断”的混合方案，并保留小型分类模型作为对照或后续优化选项。

方法 在系统中的职责
大语言模型，如本地Qwen 识别问题、提出带原文位置的事实及分类候选，将核验后的结果整理为判定理由
规则引擎 检查必要事实与适用范围，执行时间、数量及一致性比较，按已批准策略产生结果
RAG，即检索增强生成 检索适用条款，将事实、条款和程序结果提供给模型，辅助分类建议及有依据的文字说明
小型NLP分类模型 以TF-IDF加逻辑回归等方法建立对照；在标注数据充足后，评估是否适合承担稳定、重复的分类任务

这里单列“小型NLP分类模型”，是为了比较不同分类方案，而不是要求每条记录都经过所有模型。

规则检索拟采用以下步骤：

  1. 先筛选适用范围。 在用户有权访问的规则中，限定研究、中心、方案版本及事件发生时有效的规则；不能等条款送入模型后才检查访问权限。

  2. 再做混合检索（Hybrid）。 BM25按词语匹配查找，Dense用向量模型编码问题和条款，按语义相似度查找；通过RRF（倒数排名融合）合并两路排名，同一规则版本合为一个候选并保留相关证据片段。本方案按排名融合，不直接相加两种不同尺度的原始分数。

  3. 按需重排。 使用Cross-Encoder将问题描述与候选条款成对输入，重新评估相关性。是否启用重排、每路检索取多少候选，以及重排后保留多少条，均根据规则召回率、排序质量及响应时间评测确定。适用规则较少时可全部检查；必要的规则关联、例外及冲突检查不受Top-K（只取排名前K条）的截断限制。

例如，记录写“这次恶心没有录进登记表”，规则写“不良事件漏记”，两者措辞不同，向量检索可补充关键词检索。找到规则后，仍需核实事件是否发生、指定登记表是否已完整核对及对应条目是否确实缺失，不能仅凭语义相似就认定漏记。

检索和重排得分均不是分类置信度，也不能决定规则效力。规则库还应检查候选关联的例外、替代规则和必查条件，冲突检查不能仅限于重排后展示的前几条。

2. 为什么这样设计？

  • 适应不同文字表述。 同一问题可能写成简称、口语或长段描述，由模型识别问题和整理事实，比单靠固定关键词更灵活。

  • 让明确条件可复算。 时间窗口、数量差异等交给程序计算，避免让模型自行推算；同时核验输入事实，不能把“算术正确”当成“原文已理解正确”。

  • 让规则可更新、依据可追溯。 条款和分类定义放在版本化规则库中，不要求模型靠记忆回答；更新规则不必同时重新训练模型。

  • 兼顾效果与运行成本。 先用同一批有人工参考的数据比较简单分类器、大语言模型和混合方案，再决定是否增加重排、小模型训练或微调。不能预设组件越多，结果就一定更好。

纯规则难覆盖自由文本，纯模型又不能替代严格计算与版本校验，因此将两者结合。混合检索是否优于单路检索，也应通过实际评测确认。

3. 如何输出一级、二级、三级分类？

每条记录先拆成一个或多个问题项，再对每项执行以下过程：

  1. 形成候选。 模型根据原文、分类定义及相关规则提出问题类型和必要事实，保留对应引文；分类候选限定在已有分类树内。

  2. 核验并确定三级ID。 能形式化的问题由程序检查规则条件，命中后读取规则关联的三级ID；依赖文本理解的问题则核对模型建议与证据，不足以确认时保留候选或返回待核查。

  3. 查表取得上级分类。 根据三级ID查找所属的二级和一级，不让模型分别生成三个名称。若规则原来关联第四级，按第二部分的方法取得其所属第三级。

  4. 校验输出结构。 统一返回JSON，包含问题编号、各级分类ID及名称、风险等级、建议判定、判断依据、复核要求、建议措施和处理状态。Pydantic等工具检查字段类型和必填项，程序另查分类ID、上下级关系及证据引用是否有效。

例如，确认某样本间隔27分钟、低于适用规则的30分钟后，程序取得L3-PK-001，查表返回“样本管理 → PK样本管理 → 样本处理时间不足”。如果离心时间缺失，则三级分类可以为空，状态为“待补充离心时间”，不能为了填满JSON而强行归类。

格式合法不等于分类正确：即使模型选了一个存在的三级ID，也仍需检查事实是否支持该分类。模型提出的问题家族只作为检索线索，不能因一次家族判断错误就永久排除其他相关类别。

4. 如何生成风险等级、判断依据和建议措施？

风险等级： 根据已批准的风险策略和核验后的事实产生。分类、风险和建议判定分别保存，不能认为“属于AE问题就一定是高风险”，也不能把模型的不确定性直接当作低风险。关键信息不足时，风险可标为待定，同时提高核查优先级。

判断依据： 同时保留三类内容：

  • 原文事实及位置，如同一样本的采血时间和离心时间；

  • 适用规则的原文、编号和版本；

  • 程序计算或条件核验结果，如27 < 30。

这些内容组成可核对的证据链。对固定计算优先使用文字模板；需要更灵活说明时，由模型据此生成判定理由，并检查引用、数值及结论是否一致。判定理由的生成与核验也须纳入验证和授权范围：已获准的任务可自动处理并抽查，出现依据矛盾、无法可靠核验或超出授权范围时转人工。文字说明不能覆盖结构化判定。

建议措施： 从规则负责人确认的措施模板中选择，并结合当前缺失信息说明下一步该核查什么。例如，缺少离心时间时建议补充时间记录；是否接受样本等未获准自动处理的专业决定，应转交相应人员。模型不能自行增加停药、丢弃样本或修改原始记录等处置指令。

预警执行： 按已批准的预警条件确定级别、接收角色及处理时限，记录提醒是否送达、是否被确认；发送失败时重试或升级处理。已识别的紧急线索无需等待模型完成文字说明才提醒。风险等级描述问题本身，处理优先级决定先看哪一项，两者不能混为一谈。

例如，某规则明确将“样本处理时间不足”配置为中风险，则系统根据27分钟不足30分钟的事实输出该等级，并附时间证据、规则版本和计算结果；不能仅凭“少了3分钟”自行推断风险程度。多问题汇总时突出最高已识别风险和未决项，不用平均值掩盖问题。

5. 如何处理信息不足、模糊记录或一个记录包含多个问题？

情况 处理方法 例子
关键信息不足 明确返回缺失字段，不用默认值补齐后判定 只有采血时间，缺少离心时间：要求补充，不判断间隔是否不足
表述模糊、否定或推测 保留原句和候选解释，核清含义后判断，不把猜测当事实 “过了一会儿才离心”无法换算分钟；“未发现AE漏记”不能当成“发现AE漏记”
来源相互矛盾 保留各方证据，标记冲突，要求核实 原始记录写10:33，电子记录写10:46，不自行选一个时间
一条记录包含多个问题 按主体、事件和问题拆分，分别关联证据、规则、分类和状态 同时存在样本处理异常和AE漏记，分别输出两个问题
规则未覆盖或系统失败 明确返回待核查／未支持／处理失败，保留人工通道 无适用规则、模型输出无法解析，不等于该记录正常

多问题处理应检查是否漏掉业务片段、混用了不同受试者或样本的事实，以及是否把同一事件重复拆分。共享的研究和方案信息可复用，但每个问题的事件时间和证据应分别核对。覆盖了全部文字不代表已经理解正确，仍需通过多问题样本评测检查漏检和误分。

例如，一条记录同时说明“样本处理间隔27分钟”和“某次恶心已记录在原始观察中，但完整核对AE登记表后无对应条目”，系统分别建立样本问题与AE记录问题。若样本问题已完成，而AE登记表的完整性后来无法确认，则保留前者结果，将后者转为待核查，不能把整条记录标为处理完成。

四、人工复核与合规控制

1. 哪些情况需要人工复核？

初期通过人工复核检查系统表现；经验证并获授权后，明确范围内的低风险任务可自动处理并抽查。以下情况应进入人工处理队列：

  • 事实无法确认： 关键字段缺失、表述模糊、来源矛盾，或可能混用不同受试者、样本、事件的信息。

  • 规则或系统存在不确定性： 无适用规则、规则冲突、分类依据不足、模型漏拆问题，或AI生成的判定理由与原文、规则、计算结果不一致。

  • 超出自动处理范围： 未获授权的任务，以及模型、规则或数据来源变化后尚未完成重新验证的受影响任务；抽查发现异常时扩大复核范围，必要时暂停相关自动处理。

  • 涉及高风险或专业决定： 受试者安全相关的重要问题，以及药物因果关系、医疗处置等需要专业判断的事项。符合已批准条件的紧急预警可以先发送，不等待最终复核。

队列按风险和紧急程度分配负责人及处理时限，记录接收、确认和超时升级情况。不能因某个问题已处理，就关闭同一记录中的其他未决问题。

2. 人工如何确认或修改AI分类结果？

复核工作台并排展示质控原文、研究上下文、系统初判、适用规则及版本、事实证据和计算结果。复核人员逐项操作：

  1. 确认或退回。 依据充分且结果正确时确认；信息不足时填写待补充内容，也可转交相应负责人。

  2. 修改分类与意见。 从允许的三级分类中选择正确类别，系统自动回填一级、二级；风险、判定理由和建议措施可按权限调整，修改必须填写原因及依据。需要时可补充漏掉的问题，或纠正问题拆分。

  3. 更正事实并重新计算。 若模型抽错时间或关联错样本，追加经核实的事实及来源，再运行受影响的检查。原始业务资料本身有误时，应在原系统的受控流程中更正，不能在复核页直接覆盖源记录。

  4. 提交本次意见。 保存前检查权限、分类合法性、必填依据和记录版本。若他人已修改同一问题，提示重新核对，避免后一次提交覆盖前一次意见。

例如，AI误用了另一份样本的离心时间10:46，算出间隔40分钟；人工核实本份样本应为10:33后，系统重新计算为27分钟。应保留原来的抽取及初判，另存更正依据和新结果，而不是把历史中的40分钟直接改掉。

人工意见与系统结果不一致时，两者并列保留并说明理由；人工可以否定AI建议，但不能改写程序计算记录来掩盖差异。

3. 如何保留AI初判、人工修改和最终确认记录？

以记录编号、问题编号和分析批次关联完整历史，采用“新增版本，不覆盖旧结果”的方式保存：

记录层次 保存内容
输入快照 当次原文、研究上下文、来源及版本，后续事实更正及其依据
系统初判 AI候选、规则计算结果、分类、风险、判定理由、证据，以及生成模型、提示词、规则、分类树、关键词／向量索引、向量／重排模型及检索配置版本
人工修改 修改前后内容、修改原因、证据、操作人、角色及时间；补充、拆分、合并问题也保留关联
最终确认 被确认的具体结果版本、确认人及时间、最终意见和处理状态；自动处理结果另记授权策略版本，不伪装为人工确认

已确认结果如需调整，应重新打开处理流程并追加新版本；旧确认不自动适用于重新计算的结果。对重复提交做去重，避免一次点击产生多次确认记录。

除业务历史外，还记录查看、导出、规则发布等审计事件。通过分离权限、受保护的审计存储、完整性校验和备份检查降低篡改风险；不能仅凭“保存了历史”或“生成了哈希”就宣称记录不可篡改。若业务要求电子签名，应另行落实身份核验、签署含义及签名与具体记录版本的绑定。

4. 如何避免AI替代最终医学或合规判断？

不能只在页面写“仅供参考”，还应在权限和流程中落实职责边界：

  • 区分不同决定。 质控人员可在授权范围内确认分类和风险；需要医学判断的事项交相应研究医生，规则解释及例外适用交相应业务或合规负责人。完成分类复核，不等于医疗或合规处置已经完成。

  • 限制模型操作权限。 AI可以读取获准资料、提出建议，但不能自行发布规则、修改源数据、批准例外或执行停药等医疗处置。预警由后端按批准策略触发，不由模型自由决定执行权限。

  • 由后端控制确认流程。 校验人员身份、职责和处理范围，而不只是隐藏网页按钮；系统管理员权限不等于医学审批资格。需专业确认的问题，在取得对应意见前保持未完成状态。

  • 限定自动处理授权。 已明确规则、验证通过且获授权的常规任务无需人工重复判断，但不能因此扩大到未经批准的医学或合规决定；高置信度也不能绕过权限。

例如，记录显示受试者用药后住院，系统可以整理时间线并提示优先核查；但仅凭“先用药、后住院”不能判断一定由药物导致，更不能自行决定停药。相关医学判断和处置应由具备相应资格及职责的人员完成。

5. 如何保护受试者隐私和临床试验数据安全？

医疗健康信息属于敏感个人信息。接入前应明确处理目的、必要范围和合法依据，按适用要求落实告知、同意及个人信息保护影响评估，不能因数据“用于质控”就默认可以任意使用。

系统拟从以下方面控制：

  • 少收集、少传递。 优先使用受试者编码，移除无关姓名、证件号和联系方式；同时检查自由文本。模型只接收当前任务必要的片段，身份映射表分开保管。可通过映射表重新识别的数据仍需保护，不能当成匿名数据。

  • 隔离访问范围。 按角色、研究和中心分配最小权限；查询、检索、下载和导出均在后端校验。使用个人账户，管理高权限登录及会话有效期，避免共用账号。

  • 约束模型与外部连接。 在本地或获准的内网环境运行，限制外网访问，不自动回退到云端模型。原文、提示词、向量和日志不得未经批准发送到公共聊天服务或第三方接口，也不默认用于模型训练。

  • 保护存储与传输。 采用加密传输、加密存储和独立的密钥管理；数据库、模型接口不直接暴露公网。备份同样加密并限制访问，定期验证恢复能力。本地运行不代表其他人无法读取或导出数据。

  • 管理日志与保留期限。 普通运行日志避免记录完整原文；需要留存的证据放入受控存储。结合适用的试验档案要求确定保留期限，覆盖原文、派生数据、缓存和备份，依法执行归档、删除及个人权利请求。

  • 准备安全事件处置。 监测异常访问和批量导出；发现泄露或越权时及时限制访问、保全证据、排查影响，并按适用要求履行通知或报告义务。

五、实施与验证计划

1. 分几个阶段落地？

拟分五个阶段：明确业务与数据 → 建立分类基线 → 完成人工复核工作台与本地部署 → 独立验证 → 人机并行试运行及受控上线。

先选择规则明确、数据可获得的类别，完成从输入到保存结果的完整流程，再扩展其他类别和多问题记录。每阶段按交付物和验收结果推进，不因页面能运行就直接开放自动处理。分类、高风险漏报、响应时间和人工工作量等验收指标，在正式测试前由业务及质控负责人约定。

2. 每阶段交付物是什么？

阶段 主要工作 交付物与验收重点
1. 业务与数据准备 确定三级分类口径、风险策略、输入范围和数据权限；整理规则与历史记录 分类及字段字典、版本化规则库、标注指南、数据划分清单、验收标准；未解决的规则歧义不得直接转为自动判断
2. 分类基线与核心流程 在同一批开发数据上比较简单分类器、LLM和混合方案，接通问题拆分、事实提取、混合检索、按需重排与规则计算 可运行的分析接口、分类及检索对比报告、逐项证据输出、规则边界测试；根据效果与耗时确定组件及参数
3. 工作台与本地部署 实现结果查看、逐项复核、修改保存、权限和预警流程 可操作网页、本地部署包、操作说明、审计记录、备份与恢复方案；验证保存重开、越权拦截、通知失败和并发修改等场景
4. 独立验证 固定系统版本，在未参与调优的历史记录上测试，并开展高风险专项检查 三级分类评测报告、高风险漏报报告、错误归因清单、性能与安全测试结果；不达标则修正并重新安排独立验证
5. 试运行与受控上线 先让系统与人工并行工作，再按验证结果逐步开放获准任务 试运行报告、批准的使用范围与自动处理清单、监测面板、故障回退流程、版本回归测试集；持续跟踪漏报、误报和人工负担

人机并行期间先独立保存系统初判；用于独立比较的人工初判也应在查看系统输出前保存，再进入人机复核。不能用人工修改后的结果冒充系统成绩。紧急预警照常发送，已受AI提醒影响的人工意见另记为辅助后结果，不混入独立人工参考。只有满足前述验证和授权条件的低风险任务，才逐步从全量复核转为抽查。

3. 如何用历史质控记录验证三级分类准确性？

3.1 先建立可信的人工参考

从经授权的历史记录中抽取覆盖不同类别、风险、研究、中心和文字表述的样本，同时纳入多问题、信息不足及未发现异常的记录，避免只选容易分类的案例。

优先复用已有人工标注，先核查分类口径、标注完整性和质量；符合本次任务要求的直接作为评测参考，存在疑问或遗漏的再复核、补标，不要求全部重新标注。

需复核或补标的样本，由两名具备相应业务能力的人员，在不看待测系统输出的情况下独立处理；按固定的分类口径和事件发生时适用的规则，核对或补充每个问题的主体、事件、原文证据、三级分类和风险等级，分歧由指定负责人裁定。

旧标签若来自第四级，先核对其所属第三级；分类体系发生变化时保留映射依据，不能只按名称合并。资料不足以确认的问题项单独标为待核查，评测系统是否正确保留未决状态，不强制编出确定标签。同一记录中的其他已确认问题，仍纳入分类和风险评测。

3.2 先划分数据，再训练和调优

  • 训练集： 用于训练分类器、微调模型或选择提示词中的示例；预训练LLM也可以不微调，先作为基线。

  • 验证集： 用于比较方案、修改提示词、选择检索及重排数量等可调参数；业务规则和风险条件的变更仍须审批，不能只为提高分数而修改。

  • 最终测试集： 在方案固定后用于独立验收，不参与上述选择。

划分时将同一受试者、同一事件、同一原记录的修订版及重复或高度近似记录放在同一组，避免相关内容同时出现在训练和测试中。根据拟上线范围，再安排新中心、新研究或较晚时间段的验证。分组划分用于避免同一对象的信息跨集合泄漏。

模型输入只保留实际分析时可获得的原文和上下文，不包含历史人工分类字段或事后整改结论；案例检索库也不能混入测试记录的标准答案。用于拟合文本特征等处理的参数只从训练集学习。

测试时保存数据清单、生成模型、提示词、规则、分类树、关键词／向量索引、向量／重排模型及检索配置版本。若根据测试错例修改系统，这批数据随后可用于回归检查，但不能再当作全新的独立验收集。

3.3 同时看总体成绩、每类表现和漏掉的问题

先按主体、事件及证据位置，将系统输出的问题项与人工参考逐一匹配，再核对三级ID。漏掉的问题计为漏检，多报或重复拆出的项计为误报；不能只比较去重后的分类名称，否则同一类别下漏掉一个独立问题也可能被掩盖。

重点报告：

  • 单问题记录的三级准确率： 人工参考能够确定类别的记录中，有多少被系统正确分类；系统未能给出分类的记录不能从分母中删掉。

  • 每类Precision、Recall和F1： 分别看“报出来的有多少正确”“应该发现的找到了多少”，以及二者的综合表现，并列出每类样本数。

  • Micro-F1与Macro-F1： 前者汇总所有类别的正确、漏报及误报数量后计算，后者对各类F1等权平均，帮助观察少见类别是否表现较差。统计类别及无样本类别的处理方式须预先固定。

  • 整条记录完全正确率： 所有问题均找到、三级分类均正确，且没有多报的记录比例；同时单列有问题和无问题记录，避免大量无问题记录抬高成绩。

  • 转人工与失败比例： 人工参考可确定三级分类、系统却返回待核查时，属于未完成自动分类，不能算分类正确。人工参考本身未决的问题项另报处理状态是否合理。

例如，一条记录实际包含样本处理异常和AE漏记，系统只正确找到了样本问题，应记为发现一项、漏掉一项，整条记录不能算完全正确。

除最终分类外，按错误来源检查问题拆分、事实提取、适用规则检索、条件判断和文字说明，找出应改进的环节。样本不足的类别明确列出，不能仅凭总体分数认定所有类别均已验证。

检索环节单独比较BM25、Dense、RRF混合检索及混合检索加重排，固定相同的输入、规则库、权限和适用范围，参数只用验证集选择。以人工确认的必需条款为参考，检查候选召回率（应该找到的规则找到了多少）、前列结果相关性及响应时间；同时测试同义改写、问题家族误判，以及关联、例外或冲突条款是否被漏掉。不能只凭最终分类F1决定检索方案，也不预设增加向量检索或重排一定更好。

4. 如何重点控制高风险问题漏报？

4.1 单独准备高风险验证样本

除保留自然业务比例的代表性测试集外，另建高风险专项集，覆盖少见风险、多问题混合、否定或模糊表达、关键事实缺失、规则冲突及版本交界。

两类结果分别报告：代表性测试集用于估计日常表现和人工工作量，专项集用于发现薄弱环节。不能把特意增加了高风险样本的测试结果，直接换算成日常业务中的误报比例。

4.2 分开衡量“识别出来”和“及时交到人手里”

识别召回率以人工参考中的全部高风险问题为分母；此外，单独检查预警运行情况和自动放行结果：

  • 高风险识别召回率： 系统正确识别为高风险的问题占比；未识别出的部分单列为漏识别。

  • 及时预警和人工接收情况： 是否在规定时限内发出提醒、送达对应负责人并得到接收确认；风险待定但及时升级人工的情况单独记录。

  • 高风险错误放行： 统计含高风险问题却被自动作为低风险或无问题放行的记录数，并列出被漏掉的问题。错误放行比例按记录计算，分母为全部自动放行记录；没有自动放行记录时标为不适用。

例如，100个高风险问题中，系统识别出90个并及时提醒、由负责人接收，另有8个因不确定性及时升级并被接收，剩余2个未及时进入处理流程。高风险识别召回率是90%，及时进入预警或人工处理的覆盖率是98%；不能把那8个算成系统已经识别出高风险，更不能据此声称三级分类也正确。

还应跟踪接收后的处理是否超时。仅生成了一条提醒或进入队列，不代表风险已经得到处置。

4.3 在流程中设置防漏措施

  • 对全文保留安全检查。 经批准的高风险线索检查不依赖LLM先选对问题家族，也不受检索Top-K截断；发现线索时优先核查，但仍需结合否定语义和上下文，不能把关键词命中当成最终医学结论。

  • 不把不确定性当作正常。 无适用规则、关键事实缺失、输出失败或证据冲突时转人工，不自动放行；多问题记录逐项检查，低风险项完成不能覆盖高风险未决项。

  • 验证预警链路。 测试通知失败、模型超时、服务中断及无人接收；按已批准策略重试、升级或暂停受影响的自动处理，不让失败静默消失。

  • 同时控制误报和积压。 在验证集上平衡高风险召回与人工承受能力，监测无效提醒、重复提醒和处理超时，避免大量误报使重要预警被忽视。

  • 上线后继续找漏报。 不只检查已触发的预警，也抽查低风险、无异常及自动放行记录；结合后续核查结果追踪遗漏，将确认错例纳入回归测试，变更后重新验证受影响范围。

验收时同时报告高风险样本数、漏识别数量、错误放行数量及置信区间，说明估计结果的不确定性，而不只给一个百分比。样本量和验收阈值在测试前确定；有限样本中未出现漏报，也不能视为今后不会漏报。
