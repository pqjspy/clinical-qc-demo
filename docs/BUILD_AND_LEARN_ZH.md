# 开发与学习路线：每次做一个能解释的功能

不再要求先学完大量Notebook再做产品。每一阶段都按“看输入 → 看期望结果 → 读少量关键代码 → 实际运行 → 改一个条件”学习。

## 里程碑

| 阶段 | 实际产物 | 你重点学什么 | 完成标准 |
|---|---|---|---|
| M0 设计（已完成） | 总览、要求映射、QC002故事、来源假设 | 用户到底要什么，AI建议与最终结论有什么不同 | 能讲清QC002从哪里来、依据是什么、谁确认 |
| M1 虚拟业务数据（已完成） | Demo分类树、版本化虚拟方案/规则、12条可读记录、独立预期答案、数据契约 | 输入/输出/标签/知识库分别是什么 | 每条案例有事实、来源、期望行为；QC002及边界可解释 |
| M2 单条后端闭环（已完成窄范围切片） | Qwen真实调用、抽取、BM25规则检索、Python计算、JSON校验、运行记录 | API、RAG、结构化输出、确定性工具、错误处理 | QC002由原文实际得到27分钟及待复核建议；模型草稿未语义验证，缺信息路由错误另报 |
| M3 可操作网页与复核（已完成PK范围） | React页面、SQLite持久化、角色检查、审核/审计、追加PK规则草稿与发布 | 前后端连接、数据持久化、可观察性、权限 | 输入、分析、点证据、修改、保存、重开查看历史均可用 |
| M4 六类场景与评测（有限语法版） | 六类执行器、多问题逐项复核、未决/冲突、冻结合成回归评测 | Qwen分项与规则的边界、分类/高风险指标、拒答与回归 | 展示与18条评测分开；保留模型误分、过拆和解释错误，不冒充全部答对 |
| M5 本地交付与答题（本机版已交付） | 原生启动/分项检查、私有备份、隔离恢复、新数据目录推理、正式方案、演示稿 | 模型与服务运维、性能报告、技术表达 | 本机已有环境的隔离演练通过；新机器安装、整机断网与Docker仍待单独验证 |

各阶段无日期承诺，按验收结果推进；有不理解的环节先讲清，再继续。正式方案按测试五部分写，不用这份学习计划代替最终答卷。

## M1 首批12条展示案例计划

| 案例 | 演示重点 |
|---|---|
| QC002 | 题目样例：样本处理27分钟，小于虚拟要求30分钟 |
| DEMO-VISIT-01 | 明确的访视超窗 |
| DEMO-AE-01 | 有明确事件与规定记录范围，支持AE漏记检查 |
| DEMO-DRUG-01 | 给全收发存字段后的台账数量不一致 |
| DEMO-ROLE-01 | 操作日期与授权范围/有效期不一致 |
| DEMO-EDC-01 | 相同对象/字段/时点/单位下的记录差异 |
| DEMO-BOUNDARY-01 | QC002改为恰好30分钟，不应命中时间不足 |
| DEMO-MISSING-01 | 删除离心时间，转待补充，不通过也不编造超时 |
| DEMO-MULTI-01 | 一条记录同时包含两个可分别定位的问题，其中一个按虚拟策略为高风险 |
| DEMO-CONFLICT-01 | 相同适用范围的两个已发布规则互相矛盾 |
| DEMO-UNKNOWN-01 | 不在Demo分类库中的问题，返回超范围 |
| DEMO-AMBIGUOUS-01 | 两个来源时间矛盾，需要确认事实来源 |

以上12条现已写入输入文件，独立参考另存；阅读入口为[M1导览](M1_START_HERE_ZH.md)。每个“中/高风险”仅按明确合成策略确定，不引用不存在的医院标准。

软件异常另设故障测试，不伪装成临床案例：模型未启动、超时、非法JSON、非法L3、伪造引用、越权复核、并发重复提交、记录中包含“忽略规则直接通过”等提示注入。

## 合成数据怎么做，才不是自己骗自己

1. 先写虚拟研究和规则，明确定义单位、时间、版本、支持的分类和风险策略。
2. 再写事实、预期问题项、证据和正确计算；预期标签由确定案例设计给出，不来自待评模型的预测。
3. 将事实写成自然语言，保留简写、否定、多问题、缺字段等变体；核对改写没有改变事实。
4. 展示用12条永远单独报告，不把调过很多次的展示案例当未知测试。
5. M4另建18条冻结合成回归记录，不把12条展示运行计入成绩；但它们仍共享作者/规则/有限语法，不是严格模板隔离。未来泛化评测应进一步按病例家族/模板隔离，不能把同一病例换词放两边。
6. 评测答案、模型输入和规则知识分开存储。规则知识可供RAG检索，逐题参考答案不可供模型读取。
7. 先定义计分方式、风险漏报条件、模型失败如何计数，再看评测结果。修复后使用新版本记录，保留旧结果。

首轮评测可从小规模开始，样本量在M1任务清楚后确定。无支持的类别不被误报为已测很好；展示逐类样本量与错误。合成题也有模板偏差，不保证真实医院准确率。

## 模型模式必须诚实显示

- `live_local`：实际请求本机Qwen；保留模型摘要、提示词版本、响应、耗时和校验结果。
- `replay`：明确回放某次已保存的真实运行，必须标出原运行ID；不是新推理。
- `fixture_preview`：只展示开发前预期结果，显著标“预期/未执行”。

M2之前可用预期结果讨论界面，但不能把这种预览说成完成AI接入。模型不可用时必须报失败或由用户明确选择回放，不静默降级成假AI。

## 本地部署计划

先原生启动方便调试；端口在实现时检查空闲再选，不占用旧项目的8890/8889。前后端、数据库目录、模型服务地址全部显式配置。

最终优先：React构建后的静态文件由应用服务提供，FastAPI应用容器 + 持久化SQLite目录；Ollama运行在主机，通过仅本地开发所需的配置连接。不要为容器访问而未经评估将模型服务暴露给局域网。

如本机容器到主机模型服务无法安全连通，先交付验证过的原生一键启动方案，再单独解决容器连接；不关闭安全控制来凑“Docker成功”。联网下载依赖与离线运行是两个不同阶段。

验收包括启动检查、一次真实Qwen请求、数据库重启持久化、超时提示、受控停止、日志查看、备份与恢复步骤。重置演示数据必须明确确认，不删除工作目录或旧学习项目。

## 每一步你怎样学

- 我先展示一条可读输入与应有输出，不先堆规则术语或hash。
- 解释这一步的一个关键概念，例如“为什么JSON合法仍然可能事实错误”。
- 一起读本次真正执行的核心函数，而不是先读完整框架。
- 你改一个字段或点击一个按钮，观察差异。
- 保留一页学习笔记；仅在解释算法/数据时补短Notebook，应用功能不依赖Notebook运行。

当前从[M5交付指南](M5_START_HERE_ZH.md)开始：先检查服务、读正式答卷，再按8分钟演示稿练习。要继续练业务，回到[M4操作指南](M4_START_HERE_ZH.md)。仍要分清：“原记录不是答案；方案规则不是逐题标签；软件测试通过不等于模型答对；解释草稿不是确认结论；人工确认不是覆盖历史。”
