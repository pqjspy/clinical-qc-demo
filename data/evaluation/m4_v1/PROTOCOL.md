# M4 v1 冻结合成工作流评测（不是医院准确率）

18条新编记录、21个预期问题项；12个预期阳性问题，覆盖6个L3。作者先写预期再运行模型；不是Qwen给自己打分。
M1的12条案例及M2/M3练习属于开发/展示，不进入这18条。v1/v2成对案例同属eval-version-pair，不能拆到开发侧。

重要限制：这些数据与开发案例共享合成规则、作者和有限事实语法，部分是边界/重组变体。scenario_group只记录本轮病例组，不证明底层语言模板互不重叠。这是与展示分开、首次运行前冻结的合成回归评测，**不是严格模板隔离的独立泛化测试**，也不是医学专家标注。不用漂亮分数掩盖这个局限。

模型实际输入仅原文片段；不给case_id、scenario_group、逐题参考或期望结果。规则知识允许检索。先完成全部预测，再加载references计分。每条真实调用，失败不自动重试，不用预期答案兜底。

冻结输入、参考、知识、提示词/程序文件摘要、模型digest与参数。评测目录用不可覆盖started.json启动标记。已有结果不覆盖；看过错误后不修改这一轮代码/数据并重算为首次成绩。未来改进需另建新评测版本。本地文件哈希与标记是实验约束，不是防管理员篡改系统。

预先定义的计分：
- 按原文问题anchor位置做一对一匹配。匹配问题后L3相同为TP；漏问题/错误标签计FN，多出问题/错误标签计FP。重复预测不能满足两个参考。
- L3 Micro-F1汇总所有TP/FP/FN；Macro-F1固定6类（无支持类计0并显示支持数）。空预测不奖励F1。
- 分项完整率：一个记录的所有预期问题均正确分组、状态/L3/风险正确且没有额外问题。多问题子集单报。
- 完整工作流精确结果还要求优先级正确、没有硬失败或解释生成失败。
- 高风险漏检：4个高风险问题中未得到对应L3的问题数。风险低估另算；转人工不等于分类正确。
- 优先路由标志的召回与不必要优先路由分开；离线评测不写网页队列，不能据此证明真实队列投递成功。所有记录本就要求普通人工复核，不能把100%复核当准确率。
- 模型/流程失败留在全部18条分母；未尝试题单报且不能删去。解释失败时保留程序问题用于分类指标，但完整工作流计失败。
- 引用仅检查位置/规则来源/适用版本的结构有效性；不声明文字语义groundedness。缺少引用的失败不能当完美引用成绩。
- 列出每条预测、参考、问题、run_id和耗时；显示总样本数、各类支持数及错误。不给小样本分数贴“达到业界标准”。
