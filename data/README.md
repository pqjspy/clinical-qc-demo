# M1数据边界

全部合成、仅供演示。没有真实医院或患者数据；无公开论文/FDA数据；不存在临床准确率结论。

- `inputs/cases.json`：12条待分析原文与适用上下文。不要加入L3、风险或逐题答案。
- `knowledge/taxonomy.json`：六个合法路径和单独的L4候选，不是医院提供的权威库。
- `knowledge/protocols.json`：三份合成来源文件。文本可供检索和证据引用。
- `knowledge/rules.json`：九条规则版本，含隔离的两条故意冲突规则。
- `reference/expected_results.json`：展示用作者参考，不是LLM输出，不是独立评测集。生产分析路径不得读取。

输入/参考用`case_id`关联，不能据此做分类。比如`DEMO-AE-01`本身泄漏作者场景名，`build_model_input()`连这个ID也会移除，只在调用外跟踪任务。

记录中的日期和方案必须匹配。M1的`event_at`是作者明确给定的适用范围时点；M2仍需核对各问题的真实发生时点，不能把提交/检测时间替代实际操作时间。多问题跨规则版本的情况将另设测试，本批多问题发生在同一天同一版本。

修改演示数据后重新运行验证。结构验证不是医学或语义审定；参考算术复算也不表示模型已经抽取了事实。使用正式封存评测前，另建并按病例家族/模板拆分数据，不把这些练过的题混入测试。
